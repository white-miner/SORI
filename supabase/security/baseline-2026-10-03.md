# SORI 보안 기준선 (baseline) — 2026-10-03 07:37 KST

P0 보안 작업을 시작하기 **전**, 공개 anon 키(웹 앱에 들어 있는 키)로 무엇을 할 수 있는지 측정한 결과입니다.
각 단계(S1·S4·S5·S8)를 적용한 뒤 같은 스크립트를 다시 돌려 이 표와 비교합니다.

- 대상: Supabase `tieojdbzmqcmlwyqltrk` (PostgreSQL 17.6)
- **실제 쓰기는 한 번도 하지 않았습니다.** SQL 프로브는 `begin read only; set local role anon; … rollback;`, REST 프로브는 GET + `limit=0`(행 내용은 받지 않고 개수만)입니다.
- 개인정보 값은 기록하지 않고 **개수만** 적었습니다.

## 다시 돌리는 법

| 스크립트 | 실행 | 측정 내용 |
|---|---|---|
| `supabase/security/probe_anon.sql` | SQL Editor / psql / MCP `execute_sql`에서 블록(P1~P4)을 하나씩 실행 | anon 권한(`has_table_privilege`) + RLS 정책 평가로 읽기/수정/삭제 가능 행 수, INSERT 허용 여부, 민감 칼럼 개수, Storage 목록, anon이 실행 가능한 SECURITY DEFINER 함수 |
| `supabase/security/probe_anon_rest.mjs` | `SORI_ANON_KEY=<공개 anon 키> node supabase/security/probe_anon_rest.mjs` (`--json` 가능) | 실제 PostgREST로 GET 했을 때의 HTTP 상태와 `count=exact` 행 수 |

키는 저장소에 넣지 않습니다(대시보드 Project Settings > API 또는 MCP `get_publishable_keys`).
