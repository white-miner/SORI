# UI-SPEC — 고객 차트 화면 개편

브랜치: `feat/ui-customer-chart`
전제: **데이터 층은 건드리지 않는다.** 기존 데이터로 계산 가능한 것만 구현한다.

---

## 원칙

1. **읽기 API를 바꾸지 않는다.** `chartsForCustomer` · `CustomerChart` 필드 · 저장 API 전부 그대로.
2. **화면 위젯만 교체한다.** 계산은 UI 레이어의 순수 함수로 구현한다.
3. **없는 데이터는 만들지 않는다.** SOAP 4칸, 부위별 사진 세트는 P5·P4 이후. 지금은 해당 영역을 "준비 중" 이 아니라 **기존 필드로 대체**해 채운다.
4. **P0 특성화 테스트 7개는 계속 통과해야 한다.**

---

## 현재 문제 (스크린샷 기준)

| # | 문제 | 근거 |
|---|---|---|
| 1 | 고객 상세가 타일 허브 4개라 정보량 0. 기록을 보려면 1뎁스 더 들어가야 함 | `AdminChartPage` — 「1초 간편 차트 / 차트 관리 / 회원권 관리 / B/A 비교」 |
| 2 | 차트 관리 리스트에 사진 썸네일·금액 없음. 제목과 부제의 회차 번호가 어긋남 (6회차 카드에 "4회차 …" 부제) | `ChartManagementPage` |
| 3 | 회차 상세가 세로로 길고, 가장 중요한 B/A가 맨 아래. 이용 서비스·결제 항목 없음 | 회차 상세 화면 |
| 4 | B/A 영역이 검정으로 렌더됨 — 사진 없음인지 렌더 실패인지 불명 | 8회차 상세 |

## 목표 구조

```
고객 리스트
  └─ 고객 차트 (신규 — 기존 타일 허브를 대체)
       ├─ 요약 바 : 누적 방문 / 누적 결제 / 잔여 선불권 / 최근 방문 D+n
       ├─ 알림 칩 : 알러지 · 주의사항 · VIP
       ├─ 탭 : 타임라인 | 사진 | 결제
       │    └─ 타임라인 = 회차 카드 리스트 (날짜 · 시술 · 금액 · 썸네일 · 메모 1줄)
       ├─ FAB : + 새 방문 기록
       └─ 회차 카드 탭 → 회차 상세
            ├─ B/A 비교 (최상단)
            ├─ 이용 서비스
            ├─ 결제
            └─ 기록 (현재는 상담차트 + 관리계획 필드 재배치)
```

기존 타일 4개는 **삭제하지 않는다.** 상단 오버플로 메뉴(`...`)로 옮긴다.
「1초 간편 차트」는 FAB가 대체하고, 「B/A 비교」는 사진 탭이 대체한다.

## 데이터 매핑 (전부 기존 필드로 계산 가능)

UI 레이어에 순수 계산 함수를 새로 만든다. Store·Repository는 수정하지 않는다.

```dart
// lib/views/customer_chart/chart_summary.dart (신규 파일)
class ChartSummary {
  final int visitCount;        // charts.length
  final int totalPaid;         // charts 의 금액 필드 합계
  final int? remainingCredit;  // 기존 「잔여 N회」 소스 그대로 재사용
  final int? daysSinceLast;    // now - charts.first 날짜
  static ChartSummary from(List<CustomerChart> charts) { ... }
}
```

| 요약 바 항목 | 소스 |
|---|---|
| 누적 방문 | `charts.length` |
| 누적 결제 | 차트 금액 필드 합계 (필드명은 `chart_db_columns.dart` 확인) |
| 잔여 선불권 | 현재 「잔여 2회」를 그리는 소스를 그대로 사용 |
| 최근 방문 D+n | 최신 차트 날짜 기준 경과일 |

| 회차 카드 항목 | 소스 |
|---|---|
| 날짜 | 차트 날짜 필드 |
| 회차 | `visitNumber` — **부제에 중복 표기하지 않는다** (문제 #2) |
| 시술명 | 시술명 필드 |
| 금액 | 금액 필드. 없으면 금액 줄을 숨긴다 (0원 표기 금지) |
| 썸네일 | `beforeImageUrl` / `afterImageUrl` — 최대 2장 |
| 메모 1줄 | 「고객 상태 · 대화」 필드 첫 줄, 40자 말줄임 |

## 단계

각 단계마다 `flutter test` 통과 + 실기 확인 후 커밋.

### U1 — 고객 차트 화면 신설 (타일 허브 대체)

- 신규 파일 `lib/views/customer_chart/customer_chart_page.dart`
- **기존 `AdminChartPage` 를 삭제하지 않는다.** 라우트 `/app/customers/:id` 가 새 화면을 가리키게만 바꾸고, 기존 파일과 클래스는 남긴다. 문제 생기면 라우트 한 줄 되돌려 즉시 복구.
- 요약 바 4칸 + 알림 칩 + 타임라인 탭만 구현. 사진·결제 탭은 골격만.
- 데이터는 `chartsForCustomer` 한 번 호출로 끝낸다. 추가 쿼리 금지.
- 회차 카드 탭 → 기존 회차 상세 화면으로 push (이 단계에서 상세는 안 바꾼다).

**완료 조건:** 고객 이름 탭 → 1뎁스 만에 누적 방문·결제·잔여·타임라인이 보인다.

### U2 — 회차 카드 정보 밀도

- 썸네일(최대 2장) · 금액 · 메모 1줄 추가
- 회차 번호 중복 표기 제거 (문제 #2)
- 사진 없는 회차는 썸네일 자리에 빈 회색 박스 대신 **아이콘 + "사진 없음"** 표시 (문제 #4 진단에도 도움)
- 금액 0 또는 null 이면 금액 줄 자체를 숨긴다

### U3 — 회차 상세 재배치

- 섹션 순서를 **B/A → 이용 서비스 → 결제 → 기록** 으로 변경
- 「피드 공유」 토글을 최상단에서 최하단으로 이동 (사장님이 매번 보는 것이 아님)
- 이용 서비스 = 시술명 + 회차, 결제 = 금액 + 선불권 차감 여부. 기존 필드 재배치일 뿐 새 데이터 없음
- 기록 섹션은 현재 「상담 차트」 + 「관리 계획」 카드를 하나로 합쳐 표시
- 하단 고정 버튼 「수정하기」 · 「전체 차트 작성기로 열기」 유지

### U4 — 사진 탭 · 결제 탭 채우기

- 사진 탭: 고객의 전 회차 사진을 시간순 그리드로. 회차별 before/after 쌍을 한 줄로 묶는다.
- 결제 탭: 차트 row 를 결제 원장처럼 리스트업 + 상단에 누적 결제 · 잔여 선불권
- 부위별 세트 필터는 **넣지 않는다** (P4 이후)

- `chartsForCustomer` · `CustomerChart` · 저장 API 수정

## 디자인 토큰

기존 앱 스타일(흰 카드 · 연회색 배경 · 검정 CTA)을 유지한다. 프로토타입의 클레이/샌드 팔레트로 갈아타지 않는다.
프로토타입에서 가져올 것은 **정보 구조와 배치**이고, 색은 현재 앱 것을 쓴다.

- 요약 바 수치: 20~22px bold, 라벨 12px 회색
- 회차 카드: 흰 배경, 12px radius, 그림자 없음, 구분선 1px
- 알림 칩: 알러지·주의 = 붉은 계열 배경, VIP = 회색 배경
- 탭: 밑줄 인디케이터 (현재 「고객 / 리뷰」 탭 스타일 재사용)
