## 0. 한 줄 결론

차이는 모델 IQ가 아니라 **문제 정의·성공 기준·작업 단위**의 차이다.

- 퍼플렉시티+커서: *조사·계약·체크리스트·마이크로 PR*로 **파이프를 닫기 전에 UI를 쌓음**  
- 지피티: *「맵에 진짜 뷰티 샵이 중심 기준으로 뜨는가」* 하나만 보고 **데이터 통로 → 정직한 실패 → UI 단순화**를 한 번에 닫음

## 2. 원인 분석 (큰 차이 5개)

### 원인 A — 성공 기준이 “문서 완료”였음

퍼플렉시티/기획 라인은 이런 산출물을 양산했다.

- `SORI_우리지역_6시간_자동개발기획서.md` — STOP-1~6, “조사 없이 진행 금지”
- `SORI_오늘완성_100개_개발체크리스트.md` — 항목 100개
- `PRD_v7.9_REGION_MAP_*` — 맵 UX 계약, 클러스터, detent, 저장함…
- 경영/상권/목표매출/전략 에이전트까지 **같은 ‘우리지역’ 브랜드**로 묶임

에이전트에게 “막히면 멈춰라 / 가짜 LIVE 금지 / 회신 대기”가 과도하게 걸렸다.  
그 결과 **사용자 눈에 샵이 안 뜨는 상태**가 며칠씩 방치되어도, 문서는 “계약 준수 중”으로 보일 수 있었다.

지피티는 문서 100칸을 채우지 않고 **현장 성공 한 줄**만 닫았다.

### 원인 B — ‘우리지역’이 제품 두 개였음

| 제품 A (커뮤니티) | 제품 B (경영) |
|---|---|
| 글·세미나 발견 맵 | 상가 API·경쟁·목표매출 |
| `region_nearby_map_section` | `market-strategy` / PublicData |
| PRD REGION_MAP | 6시간 기획서·100체크 |

2주 동안 에이전트·조사가 **A와 B를 한 이슈로 취급**했다.  
범위가 커질수록 Cursor는 5파일 규칙·승인 대기·다른 스프린트(Chart/타이머/디자인 재구성)와 섞여 **어느 쪽도 E2E로 안 닫힘**.

지피티 복구 커밋은 **라이브 샵 파이프 + 맵 발견 UX**에 집중했다 (제품 A의 데이터 구멍).

### 원인 C — 마이크로 PR이 ‘가짜 진척’을 만듦

main 히스토리에 region 관련 PR이 매우 잘게 쪼개져 있다.

예: 카드 필드 → 반경 요약 → 네이버 링크 → 검색중심 공유 → 로컬 스냅샷 → GPS 중심 → 카테고리 → 반경칩 → 캡션 → …

각각은 규칙상 안전한 Expand다. 그러나:

- 업스트림 **페이지 미완**이면 UI 칩을 늘려도 목록은 빈/왜곡
- **업종 분류가 느슨**하면 식당이 뷰티로 섞임
- **search center가 화면마다 다르면** “샵이 안 나와요”가 재발

진척 지표가 *머지된 PR 수*가 되면, **파이프 미완인 채 UI 부채만 증가**한다.

### 원인 D — Cursor 운영 마찰이 ‘닫는 속도’를 죽임

이 저장소의 에이전트 계약:

- 수정 전 계획 → **승인 대기**
- 한 번에 **5파일**
- 커밋/푸시는 사용자 명시 전 금지
- 기존 동작 보존 · 특성화 테스트로 **현재(버그 포함) 고정**
- 타이머/차트 작업과 region을 섞지 말라는 핸드오프

이 규칙은 **운영 앱 회귀 방지**에는 좋다.  
그러나 **이미 깨진 E2E를 고치는 복구 작업**에는:

1. 파일 5개로 Edge+서비스+맵+테스트를 한 번에 못 닫음  
2. 승인 라운드가 늘수록 컨텍스트가 리셋됨  
3. 특성화 테스트가 **구식 레이아웃/샘플 UI를 지키라**고 발목을 잡음 (`e8b3346`에서 obsolete assertion 폐기)

지피티 세션은 이 마찰을 우회하고 **파이프+UI+테스트**를 한 호흡에 닫았다 (커밋 메시지상 tree 보존·테스트 정정 커밋이 그 흔적).

### 원인 E — 조사 도구(퍼플렉시티)의 역할이 ‘구현 블로커’가 됨

기획서 명시:

> 사용자가 없는 동안 퍼플렉시티 회신을 받아 반영하는 것은 할 수 없다  
> STOP: 원천 API 반경·스키마 미확정 시 슬롯 스킵

퍼플렉시티는 **근거·금지·카피**에 강하다.  
하지만 공공 API 연동 버그는 대개:

- 응답을 직접 페이지하며 재현
- Edge 로그·타임아웃·`indsLclsCd` 필터
- “부분 결과 vs 0건” UX

처럼 **코드 실행 루프**로 풀린다.  
조사 문서를 더 쌓을수록 Cursor는 구현 대신 **다음 조사 프롬프트**로 도망가기 쉽다.

## 3. ‘모델 차이’로 오해하면 안 되는 이유

| 오해 | 실제 |
|---|---|
| GPT가 더 똑똑하다 | GPT가 **닫을 단위를 작게·올바르게** 잡았다 |
| Cursor가 무능하다 | Cursor는 **계약·회귀 방지 모드**로 묶여 있었다 |
| 퍼플렉시티가 틀렸다 | 퍼플렉시티는 **연구 도구**인데 **구현 게이트**로 쓰였다 |
| 2주가 필요했다 | 2주의 상당 부분은 **범위 비대화 + 마이크로 PR + 대기** |

같은 Cursor라도 “오늘 성공 = 맵에 뷰티 N곳 + 실패면 정직 배너”로 잠그면 훨씬 빨라진다.
