# SORI 상권분석·목표매출 전략 기능 개발 계획서

> 목적: 예비 원장과 기존 뷰티샵 원장이 목표 매출을 달성하거나 매출 감소를 회복할 수 있도록, 목표 매출·손익·상권·경쟁·인구 데이터를 시각화하고 실행 가능한 가설과 행동 계획을 제공한다.

---

## 1. 제품 정의

### 1.1 해결할 사용자 문제

| 사용자 | 상황 | 해결해야 할 질문 |
|---|---|---|
| 예비 원장 | 창업 전 입지와 매출 목표를 검토 | “월 NNN만 원 매출이 가능한 입지와 운영 구조인가?” |
| 기존 원장 | 매출 또는 방문 고객 감소 | “감소 원인이 내 매장인가, 경쟁·수요 변화인가? 지금 무엇을 해야 하나?” |
| 운영자 | 광고·콘텐츠·재방문 활동의 우선순위를 정해야 함 | “이번 주 가장 매출 영향이 큰 행동은 무엇인가?” |

### 1.2 제품 원칙

1. 데이터만 나열하지 않는다. 데이터 → 해석 가능한 신호 → 검증 가설 → 행동으로 연결한다.
2. 성공 가능성, 매출, 수익을 보장하지 않는다. 모든 진단 결과는 확률적 가설과 확인 항목으로 표현한다.
3. 외부 시장 데이터와 매장 내부 데이터를 명확히 분리한다.
4. 통계 기준일·공간 단위·출처·갱신일을 모든 화면에서 확인할 수 있게 한다.
5. 개인·경쟁업체의 비공개 매출이나 민감 정보를 추정·표시하지 않는다.
6. 지도와 차트는 결론이 아니라 비교와 질문을 위한 도구다.

### 1.3 핵심 사용자 가치

```text
목표 매출 입력
→ 필요 고객/방문/가동률 계산
→ 후보 상권 또는 현재 상권 비교
→ 경쟁·인구·수요·시장 변화 시각화
→ 원인 가설 및 전략 제안
→ 오늘/이번 주/30일 실행 과제 생성
→ 실제 성과를 입력하여 다음 제안 개선
```

## 2. 범위와 비범위

### 2.1 MVP 범위

- 목표 매출, 객단가, 변동비율, 고정비, 영업일 입력
- 목표 매출 달성에 필요한 월/일 고객 수, 방문 수, 매출, 공헌이익 계산
- 지도 기반 반경 선택 및 상권 비교
- 뷰티 세부 업종별 경쟁 업소 밀도 시각화
- 인구·유동·매출·업소 수·변화율 등 공개/계약 데이터의 집계 지표 표시
- 예비 원장용 후보 지역 비교
- 기존 원장용 매출 감소 진단 가설
- 액션 플랜과 완료 체크
- 지표 정의·출처·기준일·제한사항 표시

### 2.2 MVP 이후 범위

- 다점포 비교
- 상권 자동 모니터링 및 이상 변화 알림
- 광고 플랫폼 비용·예약 데이터 자동 연동
- 상권별 시뮬레이션과 시나리오 저장
- AI 기반 자연어 질의
- 전문 컨설턴트 검토/상담 연결

### 2.3 비범위

- 개별 경쟁 매장의 비공개 매출 추정
- 매출 보장 또는 창업 추천 확정 판정
- 인구·소득·성별 등에 기반한 부당한 차별 타깃팅
- 동의 없는 고객 개인 데이터의 광고 활용
- 민감 위치 데이터의 개인 단위 추적

## 3. 핵심 계산 모델

### 3.1 용어

| 용어 | 정의 |
|---|---|
| 객단가 | 방문 1회당 평균 결제금액 |
| 변동비 | 매출/시술 건수에 비례해 증가하는 원가·수수료·소모품비 등 |
| 고정비 | 임차료, 인건비, 관리비 등 일정 기간에 비교적 고정적으로 발생하는 비용 |
| 공헌이익 | 매출에서 변동비를 차감한 금액 |
| 공헌이익률 | 매출 중 고정비와 이익을 충당할 수 있는 비율 |
| CAC | 신규 고객 1명 확보에 쓴 마케팅 비용 |

### 3.2 수식

```text
공헌이익률 = 1 - 변동비율
서비스당 공헌이익 = 평균 객단가 - 방문당 평균 변동비

목표 매출액 = (고정비 + 목표 이익) / 공헌이익률

월 필요 방문 수 = (고정비 + 목표 이익) / 서비스당 공헌이익
일 필요 방문 수 = 월 필요 방문 수 / 월 영업일

목표 이익률 기반 목표 매출액 = 고정비 / (공헌이익률 - 목표 이익률)
```

### 3.3 입력 검증

- 금액은 0 이상 정수로 저장하고 표시 시 원화 단위 포맷을 사용한다.
- 영업일은 1~31 범위로 제한한다.
- 변동비율은 0 이상 1 미만이어야 한다.
- 객단가와 방문당 변동비를 함께 입력할 경우, 변동비는 객단가보다 작아야 한다.
- 공헌이익률이 0 이하이면 계산을 중단하고 비용 구조를 수정하도록 안내한다.
- 목표 이익률은 공헌이익률보다 작아야 한다.
- 결과는 소수점 방문 수를 올림 처리하되, 원래 계산값도 보조 정보로 표시한다.

### 3.4 계산 예시

```text
고정비: 6,000,000원
목표 이익: 3,000,000원
객단가: 90,000원
방문당 변동비: 27,000원
영업일: 25일

서비스당 공헌이익 = 63,000원
월 필요 방문 = 9,000,000 / 63,000 = 142.86
월 필요 방문(올림) = 143회
일 필요 방문 = 143 / 25 = 5.72
일 필요 방문(올림) = 6회
목표 매출 = 143 x 90,000 = 12,870,000원
```

## 4. 데이터 설계

### 4.1 데이터 레이어

| 레이어 | 데이터 | 목적 | 주의사항 |
|---|---|---|---|
| 매장 내부 데이터 | 매출, 예약, 방문, 메뉴, 비용, 고객 재방문 | 개인화 진단 | 사용자 동의, 접근 제어, 최소 수집 |
| 공개 상권 데이터 | 업소 수, 인구, 유동 인구, 상권 경계, 지역 매출 집계 | 후보 상권 비교 | 출처·공간 단위·갱신일 명시 |
| 플랫폼/지도 데이터 | POI, 카테고리, 좌표, 거리 | 경쟁 분포 지도 | 중복·폐업·카테고리 오분류 정제 |
| 사용자가 입력한 조사 데이터 | 현장 관찰, 임대료, 경쟁 가격, 주차, 사진·메모 | 정성 검증 | 공개/비공개 범위 선택 |
| 산출 데이터 | 밀도, 변화율, 점수, 가설, 실행 계획 | 의사결정 지원 | 원자료와 추정치를 분리 표시 |

### 4.2 상권 데이터 최소 스키마


### 4.3 업종 체계

내부 서비스 분류와 외부 통계 분류를 별도 테이블로 관리한다. 외부 분류가 넓을 경우, 화면에서 “유사 업종 포함”이라고 표시한다.

```text
헤어 / 바버 / 네일 / 피부·에스테틱 / 메이크업 / 속눈썹·눈썹 / 타투 / 왁싱 / 복합 뷰티
```

### 4.4 데이터 품질 규칙

- 모든 숫자는 `source`, `period`, `geography`, `updatedAt` 메타데이터를 동반한다.
- 데이터가 반경 기준이 아니라 행정구역 기준이면 동일한 것으로 보이게 합산하지 않는다.
- 데이터 기간이 서로 다르면 비교 경고를 표시한다.
- 경쟁 업소는 지도 공급자의 카테고리 분류 오류를 고려해 “참고용 추정”으로 표시한다.
- 결측치는 0으로 대체하지 않는다. `데이터 없음`으로 표시한다.
- 5개 미만 등 소규모 표본은 통계 안정성 경고를 붙인다.

## 6. UX 원칙

1. 숫자를 먼저 보여주되, 숫자의 근거와 불확실성을 숨기지 않는다.
2. 사용자가 처음 60초 안에 “내 목표에 필요한 하루 방문 수”를 확인하게 한다.
3. 지도에는 한 번에 하나의 질문만 답하게 한다. 경쟁, 인구, 매출, 변화율을 동시에 켜지 않는다.
4. 빨강은 실패 판정이 아니라 “확인 필요” 상태에만 사용한다.
5. 전략 문구는 명령보다 가설형 문장을 사용한다. 예: “재방문 저하가 주원인일 수 있습니다.”
6. 모든 인사이트에는 `근거 보기`와 `행동 만들기`를 제공한다.
7. 초보 원장에게는 전문용어 툴팁을, 숙련 원장에게는 상세 수식과 데이터 표를 제공한다.
8. 접근성을 위해 차트 색상만으로 상태를 구분하지 않고 레이블과 패턴을 병행한다.

## 7. 화면 명세

### 7.1 화면 A — 목표 매출 플래너

#### 목적

목표 매출을 방문·객단가·비용·이익으로 분해해, 사업 목표를 실행 단위로 전환한다.

#### 와이어프레임

```text
┌──────────────────────────────────────┐
│ ← 목표 매출 플래너                    │
│                                      │
│ 이번 달 목표 매출                     │
│ [        12,000,000원        ]       │
│                                      │
│ 업종  [피부·에스테틱 ▾]               │
│ 평균 객단가 [ 90,000원 ]              │
│ 방문당 변동비 [ 27,000원 ]            │
│ 월 고정비 [ 6,000,000원 ]             │
│ 목표 월 이익 [ 3,000,000원 ]          │
│ 월 영업일 [ 25일 ]                    │
│                                      │
│ [계산하기]                            │
│                                      │
│ ─ 결과 ─                              │
│ 목표 달성 필요 방문                   │
│ 월 143회 · 하루 6회                   │
│                                      │
│ 필요 목표 매출 12,870,000원           │
│ 공헌이익률 70%                        │
│                                      │
│ [상권에서 가능성 검토하기 →]          │
└──────────────────────────────────────┘
```

#### 인터랙션

- 입력 중에는 결과 카드를 미리 계산하되, 유효성 오류가 있으면 결과 대신 오류 원인을 표시한다.
- 사용자가 목표 매출과 계산된 필요 매출이 다르면 차이를 설명한다.
- “상권에서 가능성 검토하기”를 누르면 선택된 업종·목표 일방문 수를 상권 화면에 전달한다.
- 계산 결과 저장은 로그인 상태에서만 가능하며, 비로그인은 로컬 임시 상태로 유지한다.

### 7.2 화면 B — 상권 탐색 지도

#### 목적

입지 또는 현재 매장 주변의 경쟁 밀도와 수요 관련 지표를 하나의 지도 맥락에서 비교한다.

#### 와이어프레임

```text
┌──────────────────────────────────────┐
│ ← 상권 탐색                           │
│ [성건동 또는 주소 검색              🔍]│
│                                      │
│ [피부·에스테틱 ▾] [반경 3km ▾]        │
│                                      │
│ ┌──────── 지도 ────────────────────┐ │
│ │  ● 내 위치/후보지                 │ │
│ │  ● 동종 업소                      │ │
│ │  ▒ 경쟁 밀도 히트맵               │ │
│ └──────────────────────────────────┘ │
│                                      │
│ [경쟁] [인구] [유동] [시장추이]      │
│                                      │
│ 동종 업소 42곳                       │
│ 1km²당 14.0곳 · 비교 지역 중 상위 35% │
│ 기준일 2026-08 · 출처 보기           │
│                                      │
│ [후보지와 비교] [현장 조사 체크리스트]│
└──────────────────────────────────────┘
```

#### 지도 레이어

| 레이어 | 기본값 | 표현 | 설명 |
|---|---|---|---|
| 후보지/내 매장 | ON | 핀 | 기준 위치 |
| 동종 경쟁 업소 | ON | 점/클러스터 | 세부 업종 필터 가능 |
| 경쟁 밀도 | OFF | 육각형 또는 히트맵 | 면적당 업소 수 |
| 주거 인구 | OFF | 단계 구분 면적 | 데이터 기간 표시 |
| 유동 인구 | OFF | 단계 구분 면적 | 시간대 선택 가능 시 제공 |
| 시장 추이 | OFF | 지도 하단 미니 차트 | 매출/업소 수 변화 |

#### UX 제약

- 모든 레이어를 동시에 활성화하지 못하게 한다. 최대 2개 레이어만 중첩한다.
- 지도 범위가 너무 넓으면 집계 정확도 경고와 함께 권장 확대 수준을 안내한다.
- 밀도는 절대 개수와 면적당 개수를 함께 보여준다.

### 7.3 화면 C — 후보 상권 비교

#### 목적

예비 원장이 최대 3개의 후보지를 목표 매출 달성 조건과 함께 비교하도록 한다.

#### 와이어프레임

```text
┌──────────────────────────────────────┐
│ ← 후보지 비교                         │
│ [후보 A 성건동] [후보 B 황성동] [+]   │
│                                      │
│ 목표: 하루 6회 방문 · 피부·에스테틱   │
│                                      │
│             성건동       황성동       │
│ 동종 업소   42           25           │
│ 업소 밀도   14.0/km²     7.2/km²      │
│ 주거 인구   18,300       22,100       │
│ 유동 지수   128          93           │
│ 시장 추이   +3.4%        +1.2%        │
│ 임대료 메모 사용자 입력  사용자 입력  │
│                                      │
│ [지표 정의 보기]                      │
│                                      │
│ 가설                                    │
│ 성건동은 유동과 경쟁이 모두 높은 편입니다.
│ 차별화 서비스와 검색 노출 검증이 필요합니다.
│                                      │
│ [현장 조사 계획 만들기]               │
└──────────────────────────────────────┘
```

#### 비교 원칙

- 종합 점수를 기본값으로 전면에 배치하지 않는다.
- 사용자가 필요하면 가중치를 설정해 개인화 비교 지표를 만들 수 있다.
- 가중치 기반 결과는 “내 기준 점수”로만 표시하고, 객관적 성공 확률처럼 표현하지 않는다.
- 지표 기간·공간 단위가 불일치하면 비교 테이블에서 눈에 띄게 경고한다.

### 7.4 화면 D — 매출 감소 진단

#### 목적

기존 원장이 내부 운영 지표와 외부 상권 지표를 함께 보고, 감소 원인에 대한 검증 가능한 가설과 우선 행동을 선택한다.

#### 와이어프레임

```text
┌──────────────────────────────────────┐
│ ← 매출 감소 진단                      │
│ 최근 3개월 매출                       │
│ 12,000,000원 → 9,840,000원  (-18%)   │
│                                      │
│ [매출] [고객 수] [객단가] [재방문]    │
│ ┌──────────── 추이 차트 ───────────┐ │
│ └──────────────────────────────────┘ │
│                                      │
│ 외부 상권 변화                         │
│ 동종 업소 +8곳 · 유동 지수 -6%        │
│                                      │
│ 확인할 가설 3개                        │
│ ① 신규 발견성 약화 가능성              │
│    근거: 고객 수 -14%, 동종 업소 증가  │
│    [근거 보기] [행동 계획]             │
│                                      │
│ ② 재방문 흐름 단절 가능성              │
│    근거: 다음 케어 예약률 -11%p        │
│    [근거 보기] [행동 계획]             │
└──────────────────────────────────────┘
```

#### 진단 규칙 예시

| 내부 변화 | 외부 변화 | 생성 가능한 가설 | 추천 행동 |
|---|---|---|---|
| 고객 수 감소, 객단가 유지 | 동종 업소 증가 | 신규 유입/발견성 약화 가능성 | 지도 프로필, 검색 키워드, B/A 콘텐츠, 신규 캠페인 점검 |
| 고객 수 유지, 객단가 감소 | 시장 매출 감소 | 할인·저가 경쟁 또는 소비 위축 가능성 | 메뉴별 공헌이익, 패키지, 가격 제안 점검 |
| 신규 감소, 재방문 유지 | 유동 인구 감소 | 외부 유입 감소 가능성 | 추천·재방문·휴면 고객 활성화 우선 |
| 신규 유지, 재방문 감소 | 외부 변화 미미 | 서비스 경험 또는 다음 케어 흐름 단절 가능성 | 다음 예약, 리마인드, 홈케어 메시지 개선 |
| 고객 수 유지, 이익 감소 | 해당 없음 | 비용·할인·수수료 증가 가능성 | 메뉴별 원가와 할인율 재계산 |

### 7.5 화면 E — 액션 플랜

```text

│ 목표: 매출 부족분 4,560,000원 해소    │
│                                      │
│ 오늘                                    │
│ □ 다음 케어 예정 고객 18명 확인        │
│ □ 60일 미방문 고객 메시지 초안 검토    │
│                                      │
│ 이번 주                                 │
│ □ 피부 관리 B/A 콘텐츠 2건 발행 준비  │
```

### 8.3 규칙 기반 MVP

MVP에서는 설명 가능한 규칙 엔진을 우선 구축한다.

```ts
type InsightInput = {
  revenueChangePct: number | null;
  customerCountChangePct: number | null;
  averageTicketChangePct: number | null;
  repeatRateChangePp: number | null;
  nextCareRateChangePp: number | null;
  competitorCountChangePct: number | null;
  footTrafficChangePct: number | null;
  marketSalesChangePct: number | null;
};

function generateHypotheses(input: InsightInput) {
  const results = [];

  if (
    input.customerCountChangePct !== null &&
    input.customerCountChangePct < -8 &&
    input.averageTicketChangePct !== null &&
    input.averageTicketChangePct > -3 &&
    input.competitorCountChangePct !== null &&
    input.competitorCountChangePct > 5
  ) {
    results.push('신규 발견성 약화 또는 경쟁 증가 가능성');
  }

  if (
    input.repeatRateChangePp !== null &&
    input.repeatRateChangePp < -5 &&
    input.competitorCountChangePct !== null &&
    Math.abs(input.competitorCountChangePct) < 3
  ) {
    results.push('재방문 경험 또는 다음 케어 흐름 단절 가능성');
  }

  if (
    input.customerCountChangePct !== null &&
    input.customerCountChangePct < -8 &&
    input.footTrafficChangePct !== null &&
    input.footTrafficChangePct < -5
  ) {
    results.push('외부 유동 감소에 따른 신규 유입 약화 가능성');
  }

  return results;
}
```

규칙은 운영 데이터가 쌓인 후 정기적으로 검증·수정한다. AI 생성 문구는 규칙 결과를 벗어나지 못하게 하고, 근거 없는 단정 문장을 금지한다.

- 데이터 기간이 오래되었으면: 화면 상단에 기준일을 표시하고 “최신 데이터 연결 전 참고용”으로 표시한다.

## 12. 구현 단계

### Phase 0 — 발견 및 데이터 적합성 검증 (1~2주)

- 실제 사용 대상 8~12명 인터뷰: 예비 원장 4~6명, 기존 원장 4~6명
- 핵심 의사결정: 업종 분류, 반경, 비교 기준, 가장 신뢰하는 지표
- 데이터 공급원 후보별 라이선스·가격·갱신 주기·공간 단위 검토
- 와이어프레임 사용성 테스트
- 성공 기준: 사용자가 5분 안에 목표 방문 수와 후보지 비교 근거를 이해

### Phase 1 — 목표 매출 플래너 (1주)

- 비용·객단가·목표 이익 입력 폼
- 계산 엔진, 입력 검증, 결과 카드
- 저장·불러오기
- 단위 테스트와 계산 골든 케이스

### Phase 2 — 지도·경쟁 분석 MVP (2~3주)

- 주소 검색, 핀 이동, 반경 선택
- 업종 필터, 경쟁 업소 점/클러스터
- 경쟁 밀도 계산 및 지도 레이어
- 데이터 출처/기준일/한계 UI
- 현장 조사 체크리스트

### Phase 3 — 후보지 비교와 상권 지표 (2주)

- 최대 3개 후보지 저장/비교
- 인구·유동·업소·시장추이 카드
- 기간/공간 단위 불일치 경고
- 개인화 가중치 비교는 실험 기능으로 제공

### Phase 4 — 매출 감소 진단 (2~3주)

- 내부 매출/예약/방문/객단가/재방문 집계
- 외부 상권 추이 결합

## 13. 완료 기준

### 13.1 기능 완료 정의

- 사용자는 유효한 입력만으로 목표 월/일 방문 수를 계산할 수 있다.
- 사용자는 지도에서 업종과 반경을 선택해 경쟁 업소 분포를 볼 수 있다.
- 모든 외부 지표에 출처·기준일·공간 단위가 표시된다.
- 사용자는 최대 3개 후보지를 동일 기준으로 비교할 수 있다.
- 기존 원장은 내부 지표와 외부 시장 변화를 함께 볼 수 있다.
- 진단 결과에는 근거·한계·검증 방법·행동이 모두 포함된다.
- 사용자는 행동을 저장하고 기한과 측정 지표를 확인할 수 있다.
- 주요 흐름이 모바일 360px 이상에서 사용 가능하다.

### 13.2 품질 완료 정의

- 목표 매출 계산 단위 테스트 100% 통과.
- 핵심 API 권한 테스트 통과.
- 데이터 없는 상태, 오래된 데이터, 기간 불일치, 지도 API 오류 상태가 모두 구현됨.
- 지도 최초 로드, 필터 변경, 비교 페이지의 성능 예산을 사전 정의하고 측정함.
- 모바일 접근성: 키보드 포커스, 레이블, 색상 대비, 스크린리더 기본 흐름 점검.
- PII가 로그·분석 이벤트·오류 추적 도구에 노출되지 않음.

## 14. 테스트 계획

### 14.1 단위 테스트

| 대상 | 핵심 사례 |
|---|---|
| 목표 계산 | 정상값, 0 고정비, 0/100% 변동비, 음수 입력, 소수점 올림 |
| 공헌이익 | 객단가보다 변동비가 큰 경우 오류 |
| 목표 이익률 | 공헌이익률 이상 목표일 경우 오류 |
| 밀도 계산 | 반경/폴리곤 면적별 업소 수 계산 |
| 가설 엔진 | 각 규칙 조건, 데이터 부족 시 결과 억제 |
| 권한 | 다른 조직의 매장/진단/계획 접근 차단 |

### 14.2 통합 테스트

- 목표 매출 플래너 입력 → 저장 → 상권 화면 전달
- 위치 선택 → 반경 변경 → 지도·지표 재조회
- 후보 3개 비교 → 비교 결과 저장
- 내부 지표 업로드/연동 → 진단 → 액션 플랜 생성
- 데이터 원천 장애 시 마지막 정상 데이터와 갱신 경고 표시

### 14.3 E2E 테스트 시나리오

```text
시나리오 1: 예비 원장이 피부샵 목표 매출을 설정하고 후보지 2곳을 비교한다.
시나리오 2: 기존 원장이 최근 3개월 매출 감소를 확인하고 재방문 개선 플랜을 만든다.
시나리오 3: 외부 데이터가 없는 지역에서도 현장 조사 플로우를 완료한다.
시나리오 4: 데이터 기간 불일치가 있는 비교에서 사용자가 경고를 확인한다.
시나리오 5: 권한 없는 사용자가 타 매장 매출 진단 API에 접근할 수 없다.
```

## 15. 무한 시도 대신: 안전한 반복 실행 프로토콜

“성공할 때까지 무한 시도”는 비용 폭주, 중복 데이터 생성, API 제한 초과, 잘못된 배포 반복으로 이어질 수 있으므로 구현 명세로 사용하지 않는다. 대신 **명확한 중단 조건과 재시도 예산을 둔 반복 개발 루프**를 Cursor Agent에 적용한다.

### 15.1 에이전트 작업 규칙

```text
1. 한 번에 하나의 작은 작업만 수행한다.
2. 변경 전 현재 구조, 관련 타입, 테스트, 환경 변수를 읽는다.
3. 구현 후 lint → typecheck → unit test → build 순서로 검증한다.
4. 실패 시 오류 원인을 분류한다.
   - 컴파일/타입 오류
   - 테스트 기대값 오류
   - 런타임 오류
   - 환경 변수/외부 서비스 미설정
   - 설계 불명확성
5. 같은 원인에 대해 최대 3회까지만 자동 수정한다.
6. 3회 실패하면 로그, 변경 내용, 재현 절차, 다음 선택지를 남기고 중단한다.
7. 데이터 삭제, 스키마 파괴 변경, 프로덕션 배포, 유료 API 호출 확대는 반드시 사용자 승인 후 수행한다.
8. 비밀키·토큰·개인정보를 코드, 테스트 fixture, 로그, 문서에 기록하지 않는다.
```

### 15.2 완료 판정 루프

```text
작업 선택
→ 요구사항/수용 기준 확인
→ 영향 파일 조사
→ 최소 변경 구현
→ 자동 검증 실행
→ 실패 원인 분석
→ 제한된 수정 재시도
→ 통과 시 변경 요약 및 다음 작업 제안
→ 실패 한도 도달 시 차단 요인 보고
```

```text

목표:
- 현재 작업의 수용 기준을 만족하는 최소 변경을 구현한다.
```

## 19. 첫 스프린트 권장 산출물

1. 목표 매출 계산 도메인 모듈과 단위 테스트.
2. 모바일 우선 목표 매출 플래너 화면.
3. 목표 매출 플래너 → 상권 탐색 화면으로 이어지는 상태 전달.
4. 지도 데이터가 아직 없어도 작동하는 목업 경쟁 지도와 데이터 출처 컴포넌트.
5. 예비 원장 5명 대상 클릭형 프로토타입 테스트 및 피드백 기록.

첫 스프린트의 성공 기준은 “사용자가 월 NNN만 원 목표를 입력하고, 필요한 하루 방문 수를 이해한 뒤, 상권 분석을 시작할 수 있는가”이다.
