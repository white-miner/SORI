## 1. 와이어프레임이 확정한 화면

### 1.1 프로토타입 탭

| 탭 | 내용 | 소리 이식 |
|----|------|-----------|
| 대시보드 | ZONE 1~5 | **핵심 화면** |
| 시뮬레이터 | 가격·가동률·재료비·영업시간 슬라이더 | Phase 후반 |
| 모바일 | 홈 요약 / 30초 시술 기록 / 월간 리포트 | 소리 기본 UX = 모바일 우선 |
| 온보딩 | 5문항 · 3분 | 필수 선행 |
| 화면 흐름 | 데이터 계층도 | 개발 SSOT |

### 1.2 대시보드 5존 (지표 설계안 = 와이어프레임 동일)

```
ZONE 1  경영자 헤드라인     ← 시간당 수익 ★ / 진짜 영업이익 / 상권 백분위 / Alpha
ZONE 2  수익 구조 해부     ← 워터폴 · BEP · 비용 비율
ZONE 3  내 위치 · 상권     ← 공공데이터 결합 (추정·출처 필수)
ZONE 4  고객 자산          ← 재방문·LTV·시술 믹스 · 소리 CRM과 직결
ZONE 5  캐파 · 시간        ← 가동률 히트맵 2장 (내 예약 | 상권 수요)
```

### 1.3 프로토타입에서 고정한 UX 판단 3가지 (분석UI.txt)

1. **BEP에 대표 인건비 포함** — 도달일·안전마진의 감정 메시지.  
2. **워터폴에서 대표 인건비만 별색** — “이건 이익이 아니라 비용”.  
3. **히트맵은 반드시 2장 나란히** — 내 예약 vs 상권 수요.

소리 UI 토큰(흰 카드·연회색·검정 CTA)을 쓰고, 와이어의 클레이/테라코타 팔레트로 **갈아타지 않는다** (UI-SPEC 가드레일과 동일).

## 2. 데이터 계층 (구현 가능성의 핵심)

| 계층 | 소스 | 소리에서의 현실 |
|------|------|----------------|
| A. 내 매출·시술 | 사장님 입력 / 연동 | 차트·방문은 있으나 **차트 row 금액 컬럼 없음** → 매출 SSOT를 **별도 입력·연동 레이어**로 두거나 P5b 금액 Expand 후 연결 |
| B. 내 비용 | 온보딩 5문항 | **신규** `shop_biz_profile` (Expand) |
| C. 상권 벤치마크 | 소진공 상가정보 API + 서울 추정매출 등 | **Edge Function + 적재 DB** · 클라이언트 키 금지 |
| D. 예약·가동 | 케어 스케줄 / 타이머 | 홈·Visit 쪽 **기존 데이터 재사용** (ZONE 5) |
| E. 고객 식별 | `customers` + `customer_charts` | ZONE 4 — **소리 강점** |

> 공공데이터는 **개별 점포 실매출을 주지 않는다.**  
> 벤치마크(기준선)만 가능. (공공데이터 사용.txt와 동일)

### 2.1 공공 API (확정 후보)

| API | 역할 | 이용 |
|-----|------|------|
| 소상공인시장진흥공단 상가(상권)정보 | 동종 점포·좌표·업종 필터 | 상업 이용 가능 · 키 서버측 |
| 서울시 상권분석서비스(추정매출 등) | 상권 추정매출·요일/시간/성연령 | 공공누리 1유형 · **출처 표기** |
| (보조) KOSIS 인구·소득 | 세그먼트 보강 | 연 단위 |

**표기 의무:** `추정` 배지 · 출처 · 기준 분기 · 경쟁 점포 **실명+추정매출 결합 금지**.

### 2.2 온보딩 5문항 (MVP 전부 여기서 계산)

1. 업종 + 주소 → **「우리 동네 연결하기」**로 행정동 코드 자동 채움 (코드는 숨김·고급만 노출)  
2. 월 고정비 합계  
3. 평균 재료비율 (또는 시술 3개 재료비)  
4. 목표 월 소득 (= 대표 인건비 기준선)  
5. 영업 요일·시간  

일상: **30초 시술 기록** (메뉴 / 금액 / 신규·재방문) — 소리의 차트 저장 플로우와 **병합 설계** 필요 (중복 입력 금지).

## 3. 탭 배치 결정 (재확정)

### 3.1 기각

| 옵션 | 이유 |
|------|------|
| 커뮤니티「우리 지역」→ 대시보드 | 피드·부스트 상품 파괴. 경영 BI ≠ 소셜 지역 피드 |
| 마이 6탭 전면 BI 교체 | 공개 브랜드 프로필(Home/Feed/Shop…) 파괴 |
| 홈 운영데스크에 5존 전부 | 시계·타이머·케어 시작 SSOT와 충돌 · 홈 비대화 |

### 3.2 확정 IA ★ (PO 2026-09-10)

```
마이페이지 탭: Home · 경영 · Shop · Asset · Seminar · AI
  (Feed 탭 제거 — 홈·커뮤니티 추천과 중복)
  └─ 「경영」탭 = 대시보드 입구 + 요약
        └─ /app/biz-dashboard   ← 독립 전체 화면 (ZONE 1~5)
              ├─ 매출 SSOT(초기): 월 수동 입력 · 년 수동 입력
              ├─ (후) 고객차트 결제 항목 연결 시 자동 합산 가능
              ├─ 시뮬레이터 / 월간 리포트: 후속 Phase
              └─ 공공 ZONE 3: Phase 3+

홈 (운영데스크)
  └─ (Phase 2+) Insight 1줄 또는 툴박스 「경영」→ 동일 라우트

커뮤니티 「우리 지역」
  └─ 변경 없음 (피드·부스트 유지)
```

**왜 마이「경영」탭 + 독립 화면인가**

- Feed는 홈·커뮤니티 추천과 기능 중복 → 탭 제거(위젯 코드는 deprecated 보관, 삭제 아님).  
- 와이어프레임 밀도는 전용 화면이 맞다.  
- 라우트 한 줄로 롤백 가능.

### 3.3 고객 모드

- **비노출.** 원장 세션 + 본인 샵만.

## 4. 소리 기존 자산과의 매핑

| ZONE | 와이어 지표 | 소리에서 바로 쓸 것 | 새로 필요한 것 |
|------|-------------|---------------------|----------------|
| 1 시간당 수익 | 매출−비용÷투입시간 | (없음 → 입력) | 월매출·비용·투입시간 |
| 1 진짜 영업이익 | 인건비 계상 | — | 목표 월 소득 |
| 1 백분위 / Alpha | 상권 대비 | — | 공공 적재 + 내 매출 |
| 2 워터폴·BEP | 비용 분해 | — | 비용 프로필 |
| 3 상권 | 밀도·추정매출·레이더 | 샵 주소/좌표 (부분) | Edge·캐시·행정동 매칭 |
| 4 고객 자산 | 재방문·이탈·믹스 | `customers`·`charts`·멤버십 | 금액·메뉴 원가(부분) |
| 5 캐파 | 가동률·히트맵 | `care_schedule`·타이머 | 상권 시간대 수요(공공) |

**주의:** U1에서 확인한 대로 `customer_charts`에 결제 금액 컬럼이 없다.  
ZONE 1~2의 “내 매출”을 차트 합으로 속이거나 0으로 보여주지 말 것.  
→ **초기(확정): 월 매출 수동 입력 + 년 매출 수동 입력** (로컬→추후 DB Expand).  
→ **후속(선택): 고객차트 결제 항목 연결 후 자동 합산** — 차트 저장 API와 별 PR.

## 7. UX 카피 · 정체성 레이어 (이식)

| 노동자 언어 | 대시보드 |
|-------------|----------|
| 손님이 없었다 | 가동률 · 공백 비용 |
| 열심히 했다 | 투입시간 · 시간당 수익 |
| 이번 달 좀 벌었다 | 사업 이익 (인건비 계상 후) |
| 경기가 안 좋다 | 상권 성장 vs 내 성장 = Alpha |

성숙도 Lv1~4 (생존→확장) — 게임화 아닌 **좌표계**. 기존 샵 티어와 **이름 충돌 시** 라벨을 `경영 단계`로 분리.
