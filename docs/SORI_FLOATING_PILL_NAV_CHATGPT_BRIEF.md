# SORI FloatingPillNav 5탭 · 화면·필드 명세 (ChatGPT 학습·UX 자문용)

**문서 목적:** ChatGPT에게 SORI의 하단 플로팅 탭 구조를 학습시키고, **미비점·어설픈 UI/UX에 대한 솔루션**을 받기 위한 사실 기준 리포트.  
**기준 tip:** `origin/main` @ `c22ba3e` (2026-09-17)  
**웹:** https://white-miner.github.io/SORI/  
**제품:** 1인 샵(에스테틱·케어) 원장용 고객관리 · 방문기록 · 전후(B/A) 사진 · 커뮤니티 앱 `sori`

## 0. ChatGPT에게 주는 역할 (이 블록을 시스템/프롬프트로 써도 됨)

당신은 SORI의 **모바일 UX 리드**다. 아래 명세는 현재 배포된 Flutter 앱의 **사실**이다.  
가정으로 기능을 추가하지 말고, 명세에 없는 화면을 “이미 있다”고 말하지 마라.

요청이 오면:

1. 먼저 **문제의 탭·모드(원장/고객)·위계 충돌**을 한 줄로 진단한다.
2. **솔루션은 구체적**이어야 한다: 라벨 제안, 정보 계층(Level 1–3), 제거/이동할 요소, CTA 1개 규칙, 빈 상태 카피, 탭 간 역할 분리표.
3. SORI 디자인 법칙에 맞춘다:
   - 한 화면 한 목적
   - filled primary CTA는 화면당 정확히 1개
   - 색=언어 (Purple=브랜드 행동, Blue=위치, Green=완료, Yellow=확인필요, Red=파괴)
   - Glass는 떠 있는 도구(플로팅바·시트)에만
4. 데이터 계약은 깨지 않는다: Visit = `customer_charts` row (`visits` 테이블 없음). Payment ≠ 선불권.
5. 답변 형식: `진단` → `제안(Before/After)` → `우선순위(Must/Should/Later)` → `검증 체크리스트`.

## 1. 플로팅바란?

| 항목 | 값 |
|---|---|
| 위젯 | `FloatingPillNav` (`lib/widgets/floating_pill_nav.dart`) |
| 위치 | 모바일 하단 플로팅 글래스 바 (높이 64, 둥근 pill, BackdropFilter 1개) |
| PC (≥800px) | 플로팅바 대신 좌측 사이드바 (`_PcSidePanel`) — **라벨이 일부 불일치** |
| 탭 수 | 고정 5개 (index 0–4) |
| 라우트 | 모드와 무관하게 동일 path. **루트 위젯만 원장/고객으로 분기** |
| 셸 AppBar | 로고 · 모드전환 · 새 게시물(+) · 알림 · 보관함 · 설정 (고객 상세에서는 AppBar 숨김 가능) |

### 1.1 모드별 라벨 (모바일)

| Index | Path | 원장(Director) | 고객(Customer) |
|---:|---|---|---|
| 0 | `/app/home` | **홈** | **홈** |
| 1 | `/app/customers` | **고객** | **케어** |
| 2 | `/app/review` | **촬영** | **리뷰** |
| 3 | `/app/community` | **커뮤니티** | **커뮤니티** |
| 4 | `/app/my` | **책상** | **마이** |

### 1.2 이미 어설픈 구조적 불일치 (ChatGPT 우선 해결 후보)

| ID | 문제 | 왜 어설픈가 |
|---|---|---|
| N1 | Path `/app/review`인데 원장은 **촬영** UI | 라우트 이름·딥링크·문서가 “리뷰”로 읽힘 |
| N2 | Path `/app/customers`인데 고객은 **케어** UI | URL과 멘탈모델 불일치 |
| N3 | 원장 Tab4 모바일 **책상** vs PC 사이드바 **마이** | 같은 탭인데 기기별 이름 다름 |
| N4 | 원장 홈 내부 스테이지 라벨이 영어 `Desk/Chart/Programs/Flow` | GNB는 한국어, 홈만 영어 |
| N5 | 고객 「리뷰」가 Tab2와 Tab4「내 리뷰」에 중복 | 어디로 가야 할지 모호 |
| N6 | 원장 「지금 처리할 일」이 Desk에서 빠지고 **책상>오늘**에만 남음 | 홈 vs 책상 역할 충돌 잔존 |
| N7 | `reviewLabel` prop(`리뷰 관리`/`리뷰 작성`)이 실질적으로 거의 안 쓰임 | 죽은 API 냄새 |

## 2. 탭별 기능 · 필드 명세

아래 “필드”는 DB 컬럼만이 아니라 **화면에 보이는 섹션·버튼·입력·빈상태 카피**를 포함한다.

### TAB 0 — 홈 (`/app/home`)

#### 원장: VisitLauncherPage

**한 줄 목적(의도):** 시술 전후 5초 glance + 즉시 촬영/차트/타이머로 들어가기.  
**실제 구조:** 상단 **스테이지 폴더 탭 4개** (영문) → 그 아래 콘텐츠.

| 스테이지 | 라벨 | 역할 | 주요 UI 필드/CTA |
|---|---|---|---|
| 0 | Desk | 피드형 운영 데스크 | **신규 고객** · **재방문 고객** · B/A 캐러셀(전/후 슬롯, `고객 연결`, 필터 `전체`) · **관리 케이스** · `즐겨찾기만` |
| 1 | Chart | 방문 차트 작성 워크스페이스 | 3단 가로 레일: 서랍 → 파일(No.N) → 방문(Today/v) · 디지트 팔레트 · 차트 시트 |
| 2 | Programs | 프로그램 판매 | 메뉴/견적 보드 · 수기 입금 원장 (외부 PG 없음). 빈상태: `아직 메뉴 보드가 없습니다` |
| 3 | Flow | 케어 타이머 | 툴박스 `타이머`/`카운트`/`계산기` · 플립시계 · **케어 시작/종료** · **고객 차트 연결** |

**Desk에서 제거된 것(2026-09):** 상단 플립시계 · 스케줄러 스트립 · 「지금 처리할 일」.  
→ 일정/할일은 책상 탭에 남았고, Desk는 퀵액션+B/A+케이스로 단순화됨.

**빈 상태 카피 예:**
- `미완성 촬영이 없습니다` / `완성된 촬영이 없습니다`
- `완성된 B/A 케이스가 아직 없습니다`
- `위 전·후 등록에서 사진을 찍고 고객에 연결해 보세요`

**1홉 이동:** 신규고객 폼 · 재방문 피커 · 스마트 가이드 카메라 · B/A 비교 · 타이머 풀스크린 · Visit 세션 뷰

**ChatGPT UX 질문 (홈 원장):**
- Desk에 일정이 없으면 “오늘 첫 고객을 어디서 시작하나?”가 약하다. CTA 위계를 어떻게 재배치할까?
- `Desk/Chart/Programs/Flow`를 한국어로 바꿀 때 멘탈모델(책상 vs Chart vs Flow) 충돌을 어떻게 풀까?
- Chart 3레일이 현장 한손 조작에 적합한가? 단순화 안은?

#### 고객: UnifiedHomeFeedPage (FeedSurface.home)

**한 줄 목적:** 가벼운 추천 glance (탐색·작성은 커뮤니티로).

| 요소 | 표시 |
|---|---|
| 헤더 | `추천 글` + CTA `게시물 보기`(→ Tab3) |
| 본문 | `오늘 보면 좋은 글` · 부제 `가벼운 추천만 보여 드려요. 탐색·작성은 커뮤니티에서.` |
| 제한 | 추천 ≤3 · Boost/탐색/우리지역 **숨김** |
| 빈상태 | `아직 피드 콘텐츠가 없어요…` |

**ChatGPT UX 질문:** 홈과 커뮤니티 추천의 중복 감각을 줄이는 카피·레이아웃은?

## 7. 한 장 요약 (ChatGPT 첫 문장용)

SORI 모바일은 하단 글래스 pill 5탭이다.  
원장: 홈(Desk/Chart/Programs/Flow) · 고객 · 촬영 · 커뮤니티 · 책상.  
고객: 홈(추천 glance) · 케어 · 리뷰 · 커뮤니티 · 마이.  
같은 URL이 모드에 따라 다른 루트를 탄다.  
가장 어설픈 지점은 (1) 라우트명과 라벨 불일치, (2) 홈↔책상 할일/일정 역할 충돌, (3) 책상 6탭 과밀, (4) 고객 리뷰 중복, (5) 영문 스테이지 라벨이다.  
ChatGPT는 기능을 늘리지 말고 **목적·CTA·카피·이동/삭제**로 UX를 고쳐라.
