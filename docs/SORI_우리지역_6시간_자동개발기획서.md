## 3. 절대 정지 규칙

아래가 필요해 보이는 순간 **그 슬롯을 건너뛴다.** 추측으로 채우지 않는다.

```text
STOP-1  원천 API 반경 단위(m/km)·최대값이 문서/실응답으로 확정되지 않음
        → 10km 칩은 유지하되 “원천 최대 반경”이라고 쓰지 않음
        → 요청 반경 ≠ 조회 반경이면 밀도는 조회 반경만 사용

STOP-2  성공 JSON item 키(bizesId, lon/lat vs cx/cy) 실응답 미확정
        → 현재 fallback 키 유지, 새 키 추정 추가 금지

STOP-3  TASIS 매출 분위 REST/파일 스키마·라이선스 미확정
        → 제공 데이터 없음 유지. 분위 숫자 생성 금지

STOP-4  행안부 15108065 · SGIS 토큰/파라미터 미확정
        → 인구 LIVE 연결 금지. 행정동 집계 참고 카피만

STOP-5  웹 CORS 헤더 실측 없음
        → 웹 직접 호출을 LIVE로 표시 금지

STOP-6  상담/방문/결제/사진/마이그레이션/Edge/키 커밋
        → 이번 6시간 범위 밖
```

### 요청문 1 — storeListInRadius 실계약 (최우선)

```text
역할: 공공데이터 API 계약 조사관. 추정 금지. 공식 페이지만 근거.

대상: 소상공인시장진흥공단 상가(상권)정보
엔드포인트: https://apis.data.go.kr/B553077/api/open/sdsc2/storeListInRadius

이미 잠긴 전제 (재서술 금지):
- 전국 영업중 상가업소, 상호·업종·주소·좌표
- HTTP 200만으로 성공 판정 금지
- LIVE_EMPTY는 resultCode 00 + 정상 body + totalCount 0일 때만

확인만 하라. 모르면 “문서 없음” 또는 “활용신청 후 상세명세 필요”.

1. 공식 상세 명세에서 cx, cy의 정의 (경도/위도 여부)와 예시 좌표
2. radius 단위(m/km)와 최대값. 2km 상한이 원천 API인지 구현체 제한인지
3. pageNo, numOfRows 지원 여부, 기본값, 최대값
4. type=json 과 type=xml 각각의 성공 응답 루트 키
5. 정상 item의 정확한 JSON 키: 업소ID, 상호, 대/중/소분류 코드·명, 도로명/지번, 경도, 위도
6. 오류 본문 예시: cmmMsgHeader vs header.resultCode
7. 10km(radius=10000 가정) 요청 시 오류 코드가 나오는지, 결과가 잘리는지
8. Access-Control-Allow-Origin 등 CORS 공식 언급 여부

산출: 표. 각 칸에 상태(공식확인/문서없음/실응답필요)와 출처 URL.
샘플 응답 전문이 있으면 개인정보·키 없이 키 이름만.
indsSclsCd 값을 추측해 적지 말 것. 코드표 원문이 있을 때만 적음.
```

