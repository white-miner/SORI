# SORI 오늘 완성 — 100개 개발 체크리스트

> 오늘의 단일 목표: **우리지역 / 상권분석 / 경영 / 목표매출 / 최적화 전략 에이전트**를 실제로 사용할 수 있는 Flutter 기능으로 완성한다.
>
> 기본 원칙: 보안 수준은 **낮음**. 사용자 요청 전에는 Supabase Edge, CLI, 프록시, 고급 권한, 감사 로그, 보안 아키텍처를 추가하지 않는다. 공공데이터는 사용자가 PowerShell에 이미 등록한 키를 이용해 Flutter 앱에서 직접 호출한다. API 키는 화면과 Git에만 노출하지 않는다.
>
> 완료 원칙: 체크만 하지 않는다. 각 항목은 UI·로직·버튼·상태·저장·테스트 중 필요한 부분이 실제로 동작할 때 완료다.

---

## 오늘의 완료 조건

```text
우리지역 진입
→ 위치/주소/지도 핀 설정
→ 업종/반경 선택
→ 공공데이터 API 직접 호출
→ 실제 주변 상가·경쟁 데이터 표시
→ 목표 매출·필요 고객 수 계산
→ 후보지 비교 또는 현재 지역 분석
→ 전략 에이전트 행동 제안
→ 실행계획 생성·저장·완료·성과 기록
```

- 개발·테스트 단계에서는 공공데이터 API 직접 호출을 우선한다.
- 모바일/Windows Flutter 앱에서 먼저 LIVE 직접 호출을 확인한다.
- 웹은 CORS·키 노출 문제로 실데이터 직접 호출이 안 되면 `UNAVAILABLE`을 정직하게 표시하되, 우리지역의 입력·계산·전략·실행계획 UX는 계속 작동해야 한다.
- `LIVE`는 실제 API 성공과 정상 파싱이 확인될 때만 표시한다.
- API 오류를 업소 0곳으로 표시하지 않는다.

- [ ] **29. 반경 상태 연결** — 반경이 API 요청·지도 원·밀도 계산·카드·비교 조건에 동일하게 반영된다.
- [ ] **30. PowerShell 키 전달 경로 구현** — 기존 등록 키를 Flutter 실행 시 `--dart-define=PUBLIC_DATA_SERVICE_KEY`로 전달하는 프로젝트 실행 스크립트를 만든다.
- [ ] **31. env.dart 직접 호출 설정 구현** — `String.fromEnvironment('PUBLIC_DATA_SERVICE_KEY')`로 키 존재 여부를 읽어 PublicDataClient에 전달한다.

- [ ] **33. PublicDataClient 직접 호출 구현** — Flutter 앱에서 소상공인시장진흥공단 상가(상권)정보 API를 직접 호출한다.
- [ ] **34. API 요청 파라미터 구현** — 좌표·반경·업종 조건을 실제 API 형식에 맞춰 전달한다.
- [ ] **35. API 응답 파서 구현** — 실제 JSON/XML 응답을 파싱하고 오류 응답과 정상 응답을 구분한다.
- [ ] **36. 업종 매핑 테이블 구현** — 공공 API 원본 업종코드/업종명과 SORI 9개 뷰티 업종을 매핑한다.
- [ ] **37. 유사 업종 표시 구현** — 정확 매칭이 아닌 경우 `유사 업종 포함`을 명확히 표시한다.
- [ ] **38. 상가 데이터 정규화 구현** — 상가업소번호, 상호, 업종, 주소, 위도, 경도, 거리, 조회시각을 내부 모델로 정규화한다.
- [ ] **39. API 상태 모델 구현** — `LIVE`, `LIVE_EMPTY`, `UNAVAILABLE`, `CACHED`, `DEMO` 상태를 분리한다.
- [ ] **40. LIVE 판정 구현** — 실제 API 성공, 정상 응답 파싱, 상류 오류 없음, 업소 존재일 때만 `LIVE`로 표시한다.

```text
- 오늘은 위 100개 항목만 개발한다.
- 기능 하나에 10분 이상 막히면 에러를 숨기지 말고, 해당 항목의 최소 작동 경로를 완성하고 다음 항목으로 진행한다.
- 한 영역을 시작하면 UI·필드·버튼·상태·저장·테스트까지 끝낸 뒤 다음 영역으로 넘어간다.
```
