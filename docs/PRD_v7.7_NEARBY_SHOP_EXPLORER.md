## 0. ZONE 3 고장 진단 (확정)

### 증상
- 「우리 동네 살펴보기」근처 샵 수·인구가 안 뜸.

### 입구 → 통로 → 출구

| 단계 | 현재 |
|------|------|
| 입구 | 경영 온보딩 저장 → `_loadMarket()` |
| 통로 | `ShopMarketService.fetch(shop: **SoriStore.shop**, admCd: 프로필)` → Edge `get-shop-market` |
| 출구 | `_Zone3Section` |

### 근본 원인 (버그)
온보딩에 적은 **주소·행정동은 `BizProfileStore`(기기 로컬)에만** 저장된다.  
ZONE 3 좌표는 **`widget.store.shop`의 address/lat/lng만** 본다.

→ 샵 설정에 주소/좌표가 비어 있으면 → `shop_coords_missing` → **상가·인구 둘 다 실패**  
→ 행정동만 연결돼도, 좌표가 없으면 상가도 실패하고 Edge 기본 좌표(경주 폴백)로 어긋날 수 있음.

### 핫픽스 (Phase 0 · 승인 후 즉시 · ≤3파일)

| 파일 | 변경 |
|------|------|
| `lib/services/shop_market_service.dart` | fetch 시 shop 주소 없으면 **프로필 address**로 지오코딩·resolve |
| `lib/views/biz_dashboard/biz_dashboard_page.dart` | `_loadMarket`에 profile address 전달 · 실패 reason을 쉬운 말로 표시 |
| (선택) Edge | 좌표 없을 때 Seoul/경주 묵시 폴백 금지 → `coords_required` 명시 |

**건드리지 않음:** 커뮤니티 피드 · 차트 · 마이그레이션.

**검증:** 온보딩에서 주소만 연결한 뒤 ZONE 3에 점포수·인구(또는 명확한 한글 에러) 표시.

## 1. 제품 문제 (PO 문장 재서술)

> “상권 분석이 뭔지 모르는 원장도, **주소만 있으면**  
> 주변에 비슷한 샵이 몇 곳인지 · 얼마나 가까운지 · 고르면 공개 통계가 뭔지  
> **지도로** 보고 싶다. 경영 숫자 입력을 먼저 강요하지 마라.”

경영 대시보드(시간당 수익·BEP)와 **역할이 다르다.**  
- 경영 = **내 장사 숫자**  
- 주변 탐색 = **동네 구경(공공 벤치마크)**

## 3. 비전 vs 현실 (정직 표)

| 원하는 것 | 오늘 코드/API | 가능 시점 |
|-----------|---------------|-----------|
| 주변 샵 **개수** | ✅ Edge 반경 카운트 | Phase 0~1 |
| **몇 m** 거리 | ⚠️ 개별 좌표 목록 미반환 (샘플 상호명만) | Phase 1 Edge Expand |
| 샵 **선택 → 상세** | ⚠️ 공공은 보통 **상가 업소 속성**(상호·업종·주소) · **개별 실매출 없음** | Phase 1~2 |
| **매출 정보** | ❌ 개별 점포 실매출 API 없음. 서울시 **상권(집계) 추정매출**만 후보 | Phase 2 · 서울 한정 |
| **지표 필터 → 지도 핀** | ❌ 맵 SDK 없음 · 지표별 점포 채색 데이터 없음 | Phase 3 |
| 경영 온보딩 없이 | ⚠️ 주소만 있으면 됨 (샵 주소 or GPS or 한 줄 입력) | Phase 1 UX |

### 법적·제품 금지선 (v7.6 유지)

- 경쟁 점포 **실명 + 추정매출**을 한 카드에 결합하지 않는다.  
- 공공 수치는 반드시 **「추정」** · 출처 표기.  
- API 키는 Edge secrets only.

→ UX 카피: 「이 샵의 매출」이 아니라  
「이 **상권(동네)의 추정 분위기**」 / 「등록된 업소 정보(상호·업종·거리)」.

## 4. 목표 UX (초보 원장)

### 4.1 3초 이해

1. 화면 상단: **「내 주변 비슷한 샵」**  
2. 한 줄: `걸어서 500m 안 · 비슷한 업종 12곳`  
3. 버튼: **지도로 보기** / **목록으로 보기**  
4. 핀·행 탭 → 바텀시트: 상호 · 업종 · 거리 · (있으면) 상권 추정 지표 · 출처  

### 4.2 주소 입구 (온보딩 강제 금지)

우선순위:

1. 이미 있는 `Shop.address` / lat·lng  
2. 없으면 **한 줄 주소** 또는 「현재 위치 허용」  
3. 카카오 `resolve_address`로 동 이름만 보여 줌 (`성건동으로 봤어요`)  
4. 행정동 코드 · 고정비 · 월급 입력 **요구하지 않음**

### 4.3 분류(필터) — MVP는 단순

| 필터 | MVP | 후속 |
|------|-----|------|
| 업종 | 에스테틱/네일/… | 세분 |
| 거리 | 300 / 500 / 1000m | 슬라이더 |
| 정렬 | 가까운 순 | 밀도·추정매출(상권) |

지도 위 **히트맵/지표 채색**은 Phase 3.

## 5. 아키텍처 (제안)

```
[주소 · GPS · Shop] ──▶ Edge get-shop-market
                         ├─ action=resolve_address
                         ├─ action=market_summary   (기존: 건수·인구)
                         └─ action=stores_in_radius (신규 Expand: 좌표·상호·업종·거리[])
                                    │
                    ┌───────────────┼───────────────┐
                    ▼               ▼               ▼
            경영 ZONE 3 수리   Nearby 목록/시트   (후) 지도 핀
                                    │
                         (후) Seoul estimated sales by *상권코드*
                              — 점포 실명과 분리 표기
```

### Edge Expand (파괴 금지)

기존 응답 필드 **유지**. 추가만:

```ts
stores: {
  ok, total_in_radius, same_category_count, sample_names, // 기존
  items?: Array<{
    name: string;
    category?: string;
    lat: number;
    lng: number;
    distance_m: number;
    address?: string;
    // 실매출 필드 넣지 말 것
  }>
}
```

### 맵

- Flutter: `flutter_map` + OSM 타일 **또는** 카카오맵 SDK (키·정책 검토)  
- 신규 패키지 = **별도 승인**

## 6. 페이즈 · 개발 요청 (에이전트/외주 공통)
