## 0. 검수 3문항 (모든 Phase 공통)

1. **우선순위가 3초 안에 보이는가** — 급한 일 / 현재 맥락 / 다음 행동  
2. **화면이 한 가지 일만 하는가** — 홈=glance · 마이오늘=사후정리 · 고객=관계 · 방문=기록 · 경영=판단 · 공개=전환  
3. **없는 상태를 UI가 발명하지 않는가** — `visitChecked` · `hasSummary` · `CareScheduleEntry.note` · B/A 공개 상태만 명확한 상태 UI

## 2. 화면별 계약 (요지)

### A. 홈 — 시술 전 5초 glance

```
주간 7일 스트립(오늘 강조 · 점/숫자)
→ 오늘 일정 최대 2~3건
→ 메모 아이콘+1줄
→ 다음 일정에만 [케어 시작] (Phase 4에서 배선; Phase 1은 CTA 자리만 가능·Timer 비조작)
```

**금지:** Day/Week 전환 · CRUD · 드래그 · 결제 · 경영 KPI · **플립시계**  
**탭:** 카드 → 마이 일정 상세(편집은 마이). Phase 1은 읽기 일치가 우선.

### B. 사장 책상 · 오늘 (Phase 2+)

순서: **업무 큐 ≤3** → **경영 peek ≤1(저강도·「경영에서 보기」만)** → **상세 스케줄**  
빈 큐: 큰 일러스트 금지 · 1줄 후 일정 바로 노출  
기록 미완료 문장: `시술 요약이 아직 없어요` (객체+행동)  
다중 일정: 큐에 고객 카드 중복 금지 · 배지=고유 customerId

### C. 고객 상세 — 관계 타임라인 (후속 Phase)

헤더 → 새 방문 기록(1차) → 다음 일정+note → 고객 메모(지속만) → 타임라인(요약·사진 수) → 사진(내부/후보/공개 분리)  
KPI 6개 · SOAP 원문 펼침 · 결제/노쇼 배지 · 상단 CTA>2 강한 버튼 **금지**

### D. 방문 기록 — 전체화면 작업대 (후속 · 큐 CTA)

10초: 요약 1문장(+칩 보조) → 기록 완료  
30초: 고객 이야기·관찰·다음 관리(접힘)  
60초+: 사진·B/A 후보  
완료=`visitChecked && hasSummary` · 사진 미입력=오류 아님 · 결제 단계 없음  
완료 후: 고객 상세/다음 일정 · 공개·메시지 CTA 강제 금지  
화면 제목: `방문 기록` / `오늘의 케어 기록` (SOAP을 첫 라벨로 강제 금지)

### E. 경영

★ `내 시간당 수익` 단독 헤드라인 · A 들어온 돈 ≠ B 선불 잔여 · 차트 1개 · 인사이트≠큐

### F. 공개 프로필

샵명·지역·철학 · 예약하기|문의하기 · 대표 B/A 0~5 · 후기·세미나 · 내부 매출/SOAP/식별정보 **비노출**

## 4. Cursor 전달용 통합 브리프 (복붙)

```md
# SORI v7.9 UI/UX 품질 브리프

## 제품 톤
SNS형 뷰티 앱·POS 복제가 아니다.
“따뜻한 임상 기록 + 조용한 경영 도구”.

## 시각 위계
- 강한 CTA 화면당 1개. 긴급 업무 카드 최대 1개.
- 아이콘에 한국어 라벨. 영어 Analytics/Dashboard 금지.
- 스키마에 없는 결제·노쇼·자동 visitChecked UI 발명 금지.

## 홈
- 5초 glance: 주간 스트립, 오늘 ≤3, 메모 1줄, (다음) 케어 시작만.
- 금지: CRUD, Day/Week 전환, 경영 KPI, 결제, 플립시계.

## 사장 책상 오늘
- 큐 ≤3 → peek ≤1 → 상세 스케줄.
- 빈 큐: 1줄 후 스케줄. 기록 미완료=visitChecked && !hasSummary.
- care_schedule 완료·Timer·postCare로 visitChecked 자동 변경 금지.

## 고객·방문
- 고객=관계 타임라인. 방문=전체화면 작업대.
- 완료=visitChecked && hasSummary. 사진 비필수.
- Customer note / schedule note / Visit 요약 자동 복제 금지.
- payment_missing·결제 배지·no_show 배지 금지.

## 경영·공개
- ★시간당 수익. A≠B. 차트 1. 인사이트≠큐. peek CTA=경영에서 보기만.
- 프로필 대표 B/A 0~5. 커뮤니티 총량 제한 없음(동의·검토). 예약|문의 CTA.
```

## 5. Phase 1 Acceptance (승인 전 잠금 · `lib/` 미착수)

**범위 한 줄:** 동일 `care_schedule` SSOT의 **홈 주간 glance + 오늘 ≤3 + note 1줄 + 마이 오늘 읽기**.  
일정 관리·CRUD·큐·Timer·경영·고객·방문·프로필 **추가 금지**.

### 5.1 Acceptance Criteria (8)

| # | Criteria | 통과 조건 |
|---|----------|-----------|
| 1 | 단일 일정 SSOT | 홈 주간 스트립과 마이 오늘 읽기는 동일 `careScheduleEntries`/`care_schedule`만 읽는다. 별도 일정 사본·스토어 **금지**. |
| 2 | 홈 범위 | 홈 스케줄면 = 주간 스트립 + 오늘 일정 **최대 3건** + note **최대 1줄**만. |
| 3 | 홈 정렬 | 오늘: **가장 가까운 미래 `scheduledAt` 우선**(종료 시각 필드 없음 · 아래 5.1-A). 이후 오름차순. 3건 초과 시 상위 3 + `+N건`. `cancelled`는 **상위 3 산정 전 제외**. |
| 4 | note 규칙 | `note` 비어 있으면 메모 아이콘·빈 행·placeholder **표시하지 않음**. 있을 때만 아이콘+1줄(말줄임). |
| 5 | 상태 표시 | `scheduled` / `completed` / `cancelled`만. `no_show`·결제·기록완료 추정 **금지**. 취소=목록·집계에서 제외. `completed`는 낮은 대비 라벨만(존재 시). |
| 6 | 읽기 전용 | 홈·마이 Phase 1: 생성·수정·삭제·드래그·상태 변경·note 편집 **비제공**. |
| 7 | Timer 격리 | `VisitTimerStore`·플립시계·타이머 조작·postCare **수정·복제·연결 금지**. |
| 8 | 비경영 원칙 | 홈에 KPI·실매출·시간당 수익·차트·상권·AI·업무 큐 **추가 금지**. |

### 5.1-A 일정 시간 및 상태 해석 가드

- Phase 1은 `VisitTimerStore`, `visitChecked`, `postCare`, 신규 상태 필드를 일정 정렬·노출에 **사용하지 않는다**.
- `CareScheduleEntry`에 **종료 시각 필드 없음** → `현재 진행 가능`의 시간 범위 판정 **불가**. Phase 1은 **가장 가까운 미래 `scheduledAt` 순**만 사용한다. (종료 시각 Expand 후 재검토)
- `cancelled`는 오늘 상위 3건·주간 스트립 점/숫자 집계·마이 오늘 목록에서 **제외**.
- 주간 점/숫자 = `cancelled` 제외 · `scheduled`(+ 필요 시 `completed`)만. 오늘 목록 기본 = `scheduled` 위주 · `completed`는 낮은 대비 라벨로만(마이).
- 마이 오늘 정렬 = `scheduledAt` 오름차순 · `cancelled` 기본 숨김.

### 5.2 홈 주간 스트립 UI

```
9월 11일 금요일
[월]…[일]  · 점 최대 3개/셀 · 일정 제목은 스트립 안에 넣지 않음
오늘: 상위 ≤3행 (고객·서비스 · 메모 있을 때만 1줄)
빈 날: 「오늘 예정된 일정이 없어요.」 1줄 · 큰 일러스트 금지
```

| 요소 | 규칙 |
|------|------|
| 오늘 셀 | 채운 배경/테두리/텍스트 중 **≥2 신호** |
| 날짜 경계 | 로컬 캘린더 주(월 시작) · §16.8 D `homeWeekAnchor` |
| 카드 | 컴팩트 행 · 강한 CTA 생략 가능(케어 시작=Phase 4) |

### 5.3 마이 오늘 읽기 (Phase 1)

홈보다 밀도만 높인 **당일 전체(또는 시간축) 목록**.  
일/주 전환 · 업무 큐 · CRUD · Timer · KPI **없음**. note 최대 1줄 · 긴 note 상세 진입 **아직 불가**.

| | 홈 | 마이 오늘 읽기 |
|--|----|----------------|
| 범위 | 주간 + 오늘 상위 3 | 당일 전체 흐름 |
| 목적 | 5초 glance | 오늘 확인 |
| CRUD/큐/Timer/경영 | 금지 | 금지 |

**Status:** **Phase 1 Approved** (2026-09-11 · AC 8 + §5.1-A) · 구현 진행  

### 5.4 승인 한정 문구 (기록)

> **Phase 1 승인:** `docs/PRD_v7.9_UI_UX_BRIEF.md` 및 MASTER §17의 Acceptance Criteria를 준수하여, 동일 `care_schedule` SSOT 기반의 홈 주간 스트립·오늘 일정 최대 3건·일정 note 1줄·마이 오늘 읽기 전용 스케줄만 구현한다. Timer, `VisitTimerStore`, 플립시계, 일정 CRUD, 업무 큐, 고객 타임라인, 방문 기록, 결제, 경영 ZONE, 공개 프로필은 범위 밖이며 수정·추가·리팩터링하지 않는다.

### 5.5 Phase 1 완료 판정

| 검수 | 통과 조건 |
|------|-----------|
| 홈 오늘 | ≤3건 · 초과 `+N건` |
| 정렬 | cancelled 산정 전 제외 · 가까운 미래 `scheduledAt` 순 · Timer/visitChecked 미사용 |
| 메모 | note 있을 때만 아이콘+1줄 |
| 주간 | 오늘 ≥2 시각 신호 · 스트립 내 일정 제목 없음 · 점=cancelled 제외 |
| 마이 | 당일 읽기 · CRUD 없음 · cancelled 숨김 · scheduledAt 오름차순 |
| Timer | 관련 코드·UI·import 변경 없음 |
| 데이터 | 동일 SSOT · 복제 store 없음 |
| 비범위 | KPI·큐·결제·고객·방문·프로필 UI 없음 |

상세 와이어·고객/방문/SOAP은 Phase 1 밖.
