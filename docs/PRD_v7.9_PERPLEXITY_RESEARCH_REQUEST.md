## 조사 질문 (표·근거 링크·짧게)

### P1. 홈 glance 스케줄 ↔ 백오피스 상세 스케줄

1인 샵/뷰티 SaaS에서 **같은 일정 데이터의 두 밀도** 사례 3개.

| 면 | 보여야 할 것 | 쓰지 말아야 할 것 |
|----|--------------|-------------------|
| 홈 glance | ? | ? |
| 상세(마이) | ? | ? |

권고: 홈=주간 스트립+오늘 하이라이트+빠른 메모 / 마이=일·주 전환+CRUD+고객 연결 — 반례가 있으면 적어라.

### P2. 빠른 메모의 위치와 수명

홈에서 “빠르게 메모”할 때 메모는  
(a) 일정 항목에 붙는 메모  
(b) 샵 공용 스크래치  
(c) 고객 메모  
중 무엇이어야 혼란이 적은가. 벤치 1–2개 + 소리 권고 1안.

### P3. 케어 타이머와 스케줄의 연결 CTA

현장 탭에 **카운트다운 시계**가 있고, 홈에는 **주간 일정**만 있을 때:  
스케줄 카드에서 “케어 시작”으로 타이머 탭/세션을 여는 UX 패턴.  
실수(다른 고객 세션) 방지 규칙 3줄.

### P4. 마이 오늘: 업무 큐 + 스케줄 세로 배치

업무 큐를 위에 둘 때 스크롤 피로·빈 큐 처리.  
“큐 없음 → 스케줄이 사실상 첫 화면”이 되어도 괜찮은지. 빈 상태 카피 3안.

### P5. 스케줄 변경 알림 (인앱 예약 OS 약함)

네이버/카카오 **외부** 예약과 인앱 `care_schedule`만 있을 때,  
「예약 취소·변경」알림의 **현실적 트리거** 후보:  
수동 상태 변경 / 고객 요청 메모 / 외부는 알림 불가 고지.  
MVP에서 약속 가능한 범위만 표로.

### P6. 커뮤니티 공개 B/A vs 공개 프로필 미러

동일 자산을 커뮤니티에 올린 뒤 프로필에 미러할 때  
중복 노출·CTA 충돌을 막는 IA 규칙 5줄.

### P7. Phase 쪼개기 (위험 낮은 순)

위 잠금을 전제로 Expand 페이즈를 **6단계 이하**로.  
각 Phase: 목적 1문장 · 성공 기준 1문장 · 절대 건드리지 말 것 1줄.  
코드 파일명 추측 금지. 제품 단위만.
