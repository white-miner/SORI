**Status:** PO 기획 지시 (v1)

**Owner:** Product / Tech Lead  
**Supersedes:** 유통사·영업사원 중심 편향 시각 (폐기)

---

## 0. 한 줄 정의

> SORI는 **원장(숙련·비숙련) · 고객(방문·탐색) · 업체 관계자**가  
> **임상 신뢰 → 트래픽 → 대화 → 거래 → 성장**을 한 루프 안에서 교환하는  
> **에스테틱 업계 필수 인프라**다.  
> 부스터·후원은 허영심 소비가 아니라 **실력 있는 솔루션을 정확한 사람에게 노출시키는 공익적 트래픽 기여**다.

## 1. 3대 주체와 세부 포지션

### 1.1 원장 축 — 전문가 / 크리에이터

| 포지션 | 니즈 | SORI가 주는 것 | 플랫폼 내 신호 |
|--------|------|----------------|----------------|
| **숙련자** (마스터·세미나 연사) | 권위 확산, 후배 양성, 세미나·고가 시술 매출 | 세미나 호스트, 티어·임상 레퍼런스, 후원 기반 노출, 위스퍼로 1:1 상담 | `tier_badge` 7+, 세미나 완료 수, 북마크·후원 누적, Facepile |
| **비숙련자** (성장형) | 임상·운영·마케팅 학습, 신뢰 확보 | 세미나 수강, AI 카피·리포트, 선배 케이스 북마크, Micro 부스터로 첫 노출 | 세미나 신청, 보관함 구독, Echo 지출(자가 부스트) |

**왜 매일 켜는가:** 오늘 올릴 케이스, 들어온 위스퍼·예약 문의, 세미나 신청, 후원·북마크 알림, AI 마케팅 초안.

## 2. 생태계 핵심 루프 — 「돈지랄」이 아닌 「가치 교환」

```
                    ┌─────────────────────────────────────┐
                    │     ① 임상·콘텐츠 (원장 생산)        │
                    │  케이스 공유 · 세미나 · AI 리포트     │
                    └──────────────┬──────────────────────┘
                                   ▼
        ┌──────────────────────────────────────────────────────────┐
        │  ② 신뢰 축적 (북마크 · 후원 · 리뷰 · 티어)              │
        │  "누가 진짜 실력자인가"를 군중지성+데이터로 증명          │
        └──────────────┬───────────────────────┬───────────────────┘
                       ▼                       ▼
        ┌──────────────────────┐   ┌──────────────────────────────┐
        │ ③ 노출·트래픽         │   │ ④ 대화·전환 (위스퍼)          │
        │ 부스터·인터리브·검색   │   │ 예약 · 세미나 · 데모 · 상담    │
        └──────────┬───────────┘   └──────────────┬───────────────┘
                   ▼                              ▼
        ┌──────────────────────┐   ┌──────────────────────────────┐
        │ ⑤ 거래 (마켓·세미나)   │   │ ⑥ 성장·재투자                 │
        │ 중고기기 · 공동구매     │   │ 비숙련→숙련 · 재후원·재방문    │
        └──────────────────────┘   └──────────────────────────────┘
```

**락인 조건:** 각 단계의 산출물이 다음 단계 입력이 되어야 한다.  
(북마크만 쌓이고 예약으로 안 가면 실패, 후원만 하고 스토리가 없으면 실패.)

## 3. 5대 기능 기둥 — 유기적 연결 설계

### 3.1 성공 임상 레퍼런스 × 북마크(보관함)

**현재 (코드베이스):** `case_archive_page`, 피드/상세 북마크 UI — **로컬 상태 위주**, 서버 SSOT·공개 신뢰 지표 미완.

**재정의:**

| 행위 | 주체 | 본질적 의미 | 다음 전환 |
|------|------|-------------|-----------|
| 북마크 | 탐색 고객·비숙련 원장 | “이 케이스/원장을 내 솔루션 후보로 인정” | 원장 프로필 방문 → 위스퍼·예약 |
| 보관함 폴더 | 비숙련 원장 | 학습 커리큘럼 | 세미나 신청 · 선배 위스퍼 |
| 공개 북마크 수 | 숙련 원장 | **검증된 레퍼런스 지표** | 검색·추천 랭킹 가중치 |

**제안 SSOT:** `case_bookmarks (user_id, chart_id, folder, visibility)`  
**피드 알고리즘 (059 확장):** `bookmark_velocity` + `supporter_echo` + `tier_rank` 복합 score.

**원장 알림:** “○○님이 당신의 ○○ 케이스를 보관함에 저장했습니다” → 감사 위스퍼 숏컷 (S2).

---

### 3.2 부스터·후원 — 본질적 가치 재정의

**현재 (Shipped):**

| 레이어 | SKU | 역할 |
|--------|-----|------|
| Micro | `boost_bump_4h` (5E) | 팔로워·후원자가 원장 케이스 상단 노출 + Boost&Fill |
| Shop AD | Spotlight | 원장 자가 마케팅 |
| VIP Overlay | Gold 39E / Platinum 149E | 기존 부스트 유지 + 프리미엄 존재감 |

**재정의 — 후원이 해결하는 3가지 실질 문제:**

1. **비숙련 원장 성장:** 선배·동료·업체 관계자가 Micro 후원 → “이 케이스 더 많은 사람이 봐야 한다” = **멘토링형 트래픽 기부**
2. **숙련 원장 권위:** 스페셜 후원 + 북마크 + 세미나 수강 = **시장이 인정한 레퍼런스**
3. **탐색 고객 정확도:** 후원·북마크가 많은 케이스가 인터리브·지역 탭 상단 → **고민 매칭 정확도↑**

**금지 UX:** “돈 쓰면 반짝이기만” 단독 메시지.  
**필수 UX:** 후원 직후 카피 — *“이 원장의 솔루션이 ○○ 고민과 비슷한 분들에게 더 잘 보입니다.”*

**경제 규칙 (유지):** Echo 소각 → `settlement_balance` 불변 (원장 정산 왜곡 없음).

**로드맵 연결:**

| Phase | 내용 |
|-------|------|
| S1–S3 ✅ | Micro + Overlay + Facepile |
| S4 | 후원 → 위스퍼 감사 숏컷, `list_my_boost_gifts` | ✅ Shipped (082) |
| S5 | 북마크·후원 복합 **「신뢰 스코어」** 공개 (원장 프로필) |
| S6 | 후원 기여 리포트 (후원자·원장 양쪽): 노출 수·저장 수·문의 전환 |

### 3.3 위스퍼 — 1:1 비즈니스/케어 핫라인

**현재:** `065`–`068` whisper on `community_posts`, composer, audience atoms (visited, followers, seminar_hosts, customer_mode…).

**재정의:** 위스퍼는 **공개 피드의 반대편 — 전환율 엔진**.

| 시나리오 | 발신 | 수신 | 트리거 | 목표 전환 |
|----------|------|------|--------|-----------|
| 감사 회신 | 원장 | 후원자 | `fan_boost` / `special_supporter` 알림 | 관계 강화·재방문 |
| 예약 상담 | 탐색 고객 | 원장 | 케이스 상세 CTA | 예약·방문 |
| 세미나 문의 | 비숙련 원장 | 숙련 원장 | 세미나 카드·북마크 | `seminar_applications` |
| 데모·공동구매 | 업체 관계자 | 타깃 원장 | 중고/리뷰 탭 관찰 후 | 마켓 거래·시술 도입 |
| 케어 Follow-up | 원장 | 방문 고객 | 케어 다이어리 | 재방문·추가 시술 |

**핵심 플로우 (S2 우선 구현):**

```
후원 알림 (shop_notifications.kind)
  → 원장 인박스 「감사 위스퍼 보내기」
  → whisper composer (recipient preset = supporter)
  → payload.reply_to_fan_gift_id
```

**B2B 위스퍼:** 업체 관계자는 **고객 모드**로 앱 사용 → 타깃 원장에게만 `explicit` atom 발송. 브랜드 로고·배지 없음.

### 3.4 고객·B2B 실물 거래 (중고기기·신제품)

**현재:** Community `marketplace` 탭, device review, `community_page` compose 흐름 — **신뢰·에스크로·평판 연동 미완**.

**재정의:** 마켓은 **임상 데이터와 후원 평판이 담보가 되는 거래**.

| 거래 유형 | 주체 | 신뢰 레이어 | 안전장치 |
|-----------|------|-------------|----------|
| 중고 기기 | 원장↔원장 | 판매자 `tier_badge`, 기기 리뷰 게시물, 거래 이력 | 에스크로(기존 037 변동 수수료 체계 연동) |
| 신제품 공동구매 | 업체↔원장 | 위스퍼 스레드 + 세미나 데모 이력 | MOQ·환불 규칙·전환 `affiliate_conversions` |
| 소비재(홈케어) | 원장→방문 고객 | 처방·케어 다이어리 연동 | 카톡 알림톡 발송 |

**평판 입력:**  
`trust_score = f(bookmark_count, supporter_echo, completed_seminars, review_rating, dispute_rate)`

**금지:** 유통사 전용 “공식 파트너” 상단 고정. **실력·거래 이력**으로만 정렬.

---

### 3.5 AI × 마케팅 × 카카오 — 획득·락인 파이프라인

**현재:** `075` AI tool SKUs (`ai_copy_marketing`, …), `kakao_alimtalk_actions`, Edge `ai-case-story`.

**재정의:** AI는 **원장의 1인 마케팅 팀** — 외부 채널로 나가야 매출이 난다.

```
임상 게시 (sparse chart)
  → Boost & Fill (078) 또는 AI 리포트
  → ai_copy_marketing (인스타·네이버용 카피)
  → [공유] 카카오 / 알림톡 (기존 고객·리드)
  → 탐색자 유입 → 북마크·후원·위스퍼
```

| 주체 | AI 산출물 | 채널 | KPI |
|------|-----------|------|-----|
| 비숙련 원장 | 마케팅 카피·해시태그 | 인스타·네이버 | 프로필 유입 |
| 숙련 원장 | 세미나 홍보·케이스 스토리 | 카톡 채널·알림톡 | 세미나 신청 |
| 방문 고객 | (수신) 케어 리마인드 | 알림톡 | 재방문율 |

**Echo 경제:** AI는 Micro 가격(2E~) — **부스터와 번들**하지 않되, “케이스 공유 → AI Fill → 카톡 발송” **온보딩 위저드**로 한 번에 연결.

## 5. 데이터·알고리즘 통합 (기술 앵커)

| 신호 | 저장소 (현재/제안) | 소비처 |
|------|-------------------|--------|
| 후원 Echo | `fan_gifts`, `boost_placements`, `boost_premium_overlays` | 059 score, Facepile, 알림 |
| 북마크 | (제안) `case_bookmarks` | 검색·추천·원장 알림 |
| 팔로우 | `shop_followers` | 위스퍼 audience, 마이페이지 |
| 위스퍼 | `community_posts.is_whisper` | 전환 funnel (예약 id payload) |
| 세미나 | `seminar_*` | 티어·신뢰·B2B |
| 거래 | `affiliate_conversions` + (제안) `market_listings` | 평판·에스크로 |
| AI job | `ai_tool_jobs` | Fill·카피·리포트 |

**피드 랭킹 (059 v2 제안):**

```
score = 0.30·recency
      + 0.25·ln(1 + supporter_echo)
      + 0.20·ln(1 + bookmark_count)
      + 0.15·tier_rank_norm
      + 0.10·overlay_tier_bonus
```

## 10. 결론

SORI가 **돈지랄 앱**이 되지 않으려면, 부스터·후원·위스퍼·북마크·거래·AI가 **각각 독립 과금 SKU가 아니라 하나의 「신뢰→노출→대화→매출」 루프**여야 한다.

- **원장**은 임상을 올리고, 신뢰를 받고, 대화로 예약을 만든다.  
- **고객**은 북마크와 후원 지표로 실력자를 고르고, 위스퍼로 문을 연다.  
- **업체 관계자**는 같은 규칙 안에서 관계 샵을 밀어주되, **플랫폼이 아닌 사람**으로 보인다.

이 문서가 이후 모든 PRD(`sponsorship`, `whisper`, `market`, `ai_tool`)의 **상위 헌법**이다.
