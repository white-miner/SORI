# SORI 우리지역·경영·전략 에이전트 글로벌 UX 리서치

> 목적: Cursor Agent가 SORI의 **우리지역 / 상권분석 / 경영 / 목표매출 / 전략 에이전트 / 실행계획**을 글로벌 상위 수준의 사용감으로 보강할 때 참고하는 단일 UX 리서치 자료.
>
> 이 문서는 기술 구조·서버·배포·보안 지시서가 아니다. 사용자가 무엇을 보고, 어떻게 이해하고, 어떤 행동을 하게 해야 하는지에 대한 제품·사용성 자료다.

---

## 핵심 결론

SORI의 우리지역과 경영 기능은 “지도와 숫자를 보여주는 화면”이 아니라, 원장이 30초 안에 다음 세 가지를 이해하고 행동하게 만드는 의사결정 도구여야 한다.

```text
1. 내 주변에 같은 업종 경쟁 매장이 얼마나 있고 어디에 있는가?
2. 내 목표 매출을 위해 하루/월 몇 명의 고객이 필요한가?
3. 그래서 오늘 무엇을 해야 하는가?
```

이를 위해 SORI는 **경쟁 → 목표 → 행동** 순서로 정보를 보여준다.

```text
우리지역
위치·업종·반경
→ 경쟁 수·밀도·분포
→ 목표매출과 필요 방문 연결
→ 현장 조사/전략/실행계획

경영
목표와 현재 차이
→ 고객 수·객단가·재방문 레버
→ 근거 기반 가설
→ 오늘/이번 주/30일 행동
```

# 1. 뷰티 경영 KPI 리서치

## 사용자 문제

- 원장은 매출이 줄었을 때 원인을 고객 수, 객단가, 재방문, 예약 중 어디에서 찾아야 하는지 모른다.
- 많은 숫자를 보여주면 판단이 쉬워지는 것이 아니라, 오히려 오늘 무엇을 해야 할지 알 수 없어진다.
- 소규모·1인 운영자는 복잡한 회계 대시보드보다 오늘과 이번 주의 운영 행동이 필요하다.

## 참고 사례

### Square Appointments

Square의 예약 성과 보고서는 재방문율, 사전예약, 예약 가동률 같은 운영 지표를 보고, 날짜·위치·직원·서비스별로 성과를 나눠 보게 한다. 팀 운영뿐 아니라 1인 사업자도 자신 또는 사업 전체의 실시간 성과를 확인할 수 있다.

**SORI에 가져올 원칙**

```text
매출만 보지 않는다.
매출을 고객 수 / 객단가 / 재방문 / 다음 예약으로 나눠 본다.
첫 화면에는 행동과 연결되는 핵심 지표만 둔다.
```

### Fresha

Fresha는 살롱 운영에서 판매, 예약, 고객, 재무를 한 플랫폼 안에서 연결해 본다. 보고서와 분석은 매출·팀·재무·예약·고객 관계를 운영 결정에 쓰는 방식이다.

**SORI에 가져올 원칙**

```text
데이터를 기능별로 분리해도, 원장은 하나의 사업 흐름으로 이해해야 한다.
예약 → 방문 → 다음 케어 → 재방문 → 매출의 연결을 보여준다.
```

### Vagaro

Vagaro는 대시보드 위젯, 고객 유지, 재예약, 신규/기존 고객 비교, 예약·판매 보고서를 운영 판단 자료로 제공한다.

**SORI에 가져올 원칙**

```text
신규 고객과 재방문 고객은 분리한다.
예약이 잡혔는지와 실제 방문이 일어났는지를 분리한다.
```

## SORI 경영 첫 화면 원칙

첫 1뷰포트에는 KPI를 4개만 우선 배치한다.

| 우선 KPI | 사용자가 이해할 질문 | 연결 행동 |
|---|---|---|
| 목표 대비 매출 차이 | 이번 달 얼마나 부족한가? | 목표 다시 계산 |
| 하루 필요 방문 | 오늘 몇 명이 더 필요한가? | 예약/신규 유입 계획 |
| 재방문율 | 기존 고객이 다시 오는가? | 다음 케어·리마인드 점검 |
| 다음 케어 예약률 | 다음 방문이 미리 잡히는가? | 방문 종료 예약 흐름 점검 |

**피해야 할 것**

```text
첫 화면의 10개 이상 KPI
기간 기준이 없는 증감률
좋아요·조회수처럼 매출 행동과 바로 연결되지 않는 장식 숫자
숫자만 있고 행동 CTA가 없는 카드
```

# 2. 신규·재방문·사전예약 리서치

## 사용자 문제

- 매출이 감소해도 신규 유입 문제인지 재방문 문제인지 구분하지 못한다.
- 방문은 있었지만 다음 예약이 없으면 미래 매출이 불안정해진다.
- “재방문율이 낮다”는 정보만으로는 무엇을 바꿔야 할지 알 수 없다.

## 글로벌 패턴

Square는 재방문과 사전예약, 예약 가동률을 함께 보고, Vagaro는 신규·기존 고객의 예약을 비교하고 고객 유지 행동을 추적한다.

## SORI 적용

```text
진단 순서:
매출 변화
→ 고객 수 변화
→ 신규 고객 변화
→ 재방문 고객 변화
→ 객단가 변화
→ 다음 케어 예약률
```

### 추천 카드 문구

```text
신호:
신규 고객은 유지되고 있어요.

근거:
최근 4주 신규 방문은 이전 4주와 비슷합니다.

가능한 해석:
재방문 또는 다음 케어 흐름을 먼저 확인할 필요가 있어요.

오늘 할 행동:
60일 미방문 고객 목록을 확인하세요.

30일 지표:
다음 케어 예약률 27% → 35%.
```

# 3. 우리지역 경쟁 분석 리서치

## 사용자 문제

- “경쟁업소가 많다”만으로 창업 또는 매출 회복 여부를 판단하려 한다.
- 지도에 업소가 많으면 읽기 어렵고, 적으면 기회인지 수요 부족인지 알 수 없다.
- 원장은 경쟁 매장의 실제 매출을 알고 싶어 하지만 공공데이터로는 개별 매출을 알 수 없다.

## 글로벌 기준

Google의 로컬 검색 원칙은 관련성, 거리, 인지도/두드러짐을 중심으로 설명된다. 정확한 업종 정보, 위치, 리뷰·평점·웹상 존재감 등은 발견성에 영향을 줄 수 있다.

## SORI에 필요한 경쟁 분석 4축

| 축 | 보여줄 데이터 | 사용자 행동 |
|---|---|---|
| 거리 | 기준 위치에서 km/m | 가까운 경쟁 확인 |
| 업종 관련성 | 동종 / 유사 업종 | 직접 경쟁 범위 판단 |
| 발견성 | 리뷰·평점·프로필 정보, 실제 연결 시만 | 지도/검색 노출 조사 |
| 서비스 구조 | 메뉴·가격·예약·운영시간, 실제 확인 시만 | 현장 조사 |

### SORI가 보여주면 안 되는 것

```text
특정 샵의 실제 매출 추정
이 지역은 성공한다는 단정
경쟁 위험 점수만으로 결론 내리기
좋은 상권 / 나쁜 상권 라벨
```

### SORI가 보여줘야 하는 것

```text
동종 업소 수
경쟁 밀도
거리·분포
동종/유사 업종 구분
현장 조사 항목
공식 지역·업종 집계 매출 수준과의 비교
```

# 4. 지도·장소 카드·클러스터 리서치

## 사용자 문제

- 지도 위 마커가 많으면 어느 업소가 중요한지 알 수 없다.
- 지도를 보는 중 장소 상세를 열면 지도 맥락을 잃는다.
- 지도만 제공하면 접근성·검색성·비교성이 떨어진다.

## 글로벌 패턴

Apple Maps는 위치·업소·랜드마크 검색 후 장소 카드에서 핵심 정보를 확인하게 한다. Google Maps의 marker clustering은 인접 마커를 묶고 확대 수준에 따라 개별 마커를 드러내 지도 전체를 읽기 쉽게 만든다.

## SORI 지도 정보 구조

```text
검색
→ 위치 선택
→ 업종/반경 filter chip
→ 지도 중심 이동
→ 클러스터 또는 개별 마커
→ 장소 카드
→ 경쟁 조사 목록 저장 또는 네이버지도 보기
```

### 줌 수준별 정보

| 지도 상태 | 보여줄 것 |
|---|---|
| 줌아웃 | 클러스터 수, 경쟁 밀도 레이어 |
| 중간 줌 | 클러스터, 선택 업종 분포 |
| 줌인 | 개별 업소 마커, 거리, 업종 |

### 장소 카드 최소 정보

```text
상호명
동종/유사 업종 배지
기준 위치에서 거리
주소
공공데이터 기준 시각
[경쟁 조사에 저장]
[네이버지도에서 보기]
```

### 지도 하단 고정 요약

```text
3km 반경
피부·에스테틱 42곳
경쟁 밀도 1.5곳/km²
[목록 보기]
```

# 5. 검색·필터·반경 선택 리서치

## 사용자 문제

- 사용자는 정확한 주소를 모를 수 있고, 동네 이름으로 탐색하고 싶다.
- 업종과 반경을 바꿨을 때 결과가 바뀌는지 즉시 확인하고 싶다.
- “필터 적용” 버튼이 많으면 반복 탐색이 느려진다.

## 글로벌 패턴

Material Design 3는 검색에 추천·제안·최근 검색을 연결할 수 있으며, Filter Chip은 선택 상태를 드러내고 결과를 좁히는 데 적합하다.

## SORI 적용

### 검색창

```text
Placeholder:
동네 또는 주소 검색

입력 전:
현재 매장 위치
최근 분석 지역
저장한 후보지

입력 후:
주소·동네 제안
결과 선택
→ 지도 중심 이동
→ [이 위치로 분석]
```

### 필터

```text
[피부·에스테틱 ▼]
[3km ▼]
[동종만 ✓]
[유사 업종 포함]
```

### 규칙

```text
필터 변경 즉시 지도·목록·경쟁 밀도·전략을 갱신한다.
별도의 “적용” 버튼은 기본적으로 만들지 않는다.
반경과 업종은 분석 조건으로 항상 화면에 남겨둔다.
```

# 6. 목표 매출 시뮬레이션 리서치

## 사용자 문제

- 예비 원장이나 전업주부 창업 준비자는 매출 목표를 고객 수와 일상 운영 시간으로 번역하기 어렵다.
- 고정비·변동비·공헌이익 같은 회계 용어는 초보자에게 부담스럽다.
- “월 500만 원”이라는 목표가 실제 하루 업무량과 맞는지 알기 어렵다.

## 핵심 UX 원칙

회계 수식보다 먼저 **하루의 운영 모습**으로 결과를 번역한다.

### 추천 입력 순서

```text
1. 한 달에 얼마를 벌고 싶은가?
2. 고객 한 명에게 평균 얼마를 받을 것인가?
3. 하루 몇 명까지 받을 수 있는가?
4. 한 달에 며칠 일할 수 있는가?
5. 고정비와 변동비는 얼마인가?
```

### 추천 결과 구조

```text
현재 계획
하루 2명 × 8만원 × 20일
= 월 예상 매출 320만원

원하는 목표
월 500만원

차이
월 180만원

가능한 조정
A. 하루 고객 2명 → 약 3.1명
B. 고객당 평균 매출 8만원 → 12.5만원
C. 고객 수와 객단가를 함께 조정
```

### 계산 기준

```text
공헌이익 = 객단가 - 방문당 변동비
공헌이익률 = 공헌이익 / 객단가
필요 매출 = (고정비 + 목표 이익) / 공헌이익률
월 필요 방문 = ceil((고정비 + 목표 이익) / 공헌이익)
일 필요 방문 = ceil(월 필요 방문 / 월 영업일)
```

### 지역 매출 비교 원칙

국세청 생활업종 통계는 업종/지역과 연 매출 수준을 입력하면 지역·업종 집계 매출 수준과 사업자 수 등을 보여준다. SORI는 이를 이용해 목표 매출이 **지역·업종의 공식 집계 구간에서 어느 수준인지** 비교할 수 있다.

```text
가능:
“월 500만원 목표는 이 지역 동종 업종의 공식 집계 매출 수준에서 어느 구간인지”

불가능/금지:
“이 목표는 A피부샵 실제 매출과 같다”
```

# 7. 후보지 비교 리서치

## 사용자 문제

- 예비 원장은 집 근처, 유동 지역, 임대료가 낮은 지역을 같은 기준에서 비교하기 어렵다.
- 경쟁이 낮은 지역을 무조건 좋은 후보지로 오해할 수 있다.
- 후보지 간 데이터 기간·반경·업종 범위가 다르면 비교가 왜곡된다.

## SORI 후보지 비교 원칙

```text
최대 3개 후보지
동일 업종
동일 반경
동일 가능한 기간
```

### 비교 표

| 항목 | 의미 |
|---|---|
| 동종 업소 수 | 절대 경쟁 수 |
| 경쟁 밀도 | 면적당 경쟁 수 |
| 실제 연결된 수요 지표 | 주거/유동/시장 지표, 제공되는 경우만 |
| 변화 | 업소 수·지표의 비교 가능 변화 |
| 사용자 메모 | 임대료, 주차, 접근성, 관찰 내용 |

### 비교 결과 카피

```text
좋지 않은 표현:
A 지역이 가장 좋은 입지입니다.

좋은 표현:
A 지역은 경쟁과 유동이 함께 높은 편입니다.
가격·리뷰·서비스 차별화와 실제 도보 동선을 현장에서 확인해보세요.
```

# 8. 전략 에이전트 신뢰 UX 리서치

## 사용자 문제

- AI가 이유 없이 “광고하세요”, “가격을 올리세요”라고 하면 신뢰하지 않는다.
- 데이터가 부족한데도 단정하면 사용자에게 잘못된 경영 결정을 유도할 수 있다.
- 분석 결과가 행동으로 이어지지 않으면 도구를 다시 열 이유가 없다.

## 전략 카드 표준 구조

```text
확인된 신호
→ 근거
→ 가능한 해석
→ 현장에서 확인할 것
→ 오늘 할 행동
→ 이번 주 행동
→ 30일 성공 지표
→ 데이터 한계
```

### 예시: 재방문 저하

```text
확인된 신호:
최근 재방문율이 낮아졌어요.

근거:
지난 4주 재방문율 27%
이전 4주 재방문율 38%

가능한 해석:
다음 케어 예약 또는 리마인드 흐름을 점검할 필요가 있어요.

오늘 할 행동:
60일 미방문 고객 목록을 확인하세요.

30일 지표:
다음 케어 예약률 27% → 35%.

데이터 한계:
서비스별 권장 재방문 주기가 다르면 재방문율 비교에 영향을 줄 수 있어요.
```

### 데이터 부족 상태

```text
재방문 데이터를 연결하면 유지 전략을 제안할 수 있어요.
[고객/방문 데이터 확인]
```

전략을 만들지 않는 것도 좋은 UX다. 근거가 없으면 사용자에게 필요한 입력과 다음 행동만 보여준다.

# 9. 실행계획·행동 전환 리서치

## 사용자 문제

- 분석을 보고도 다음 행동을 기억하지 못한다.
- “이번 주 해야 할 일”이 너무 많으면 실행하지 않는다.
- 완료 표시만 있고 성과 측정이 없으면 어떤 전략이 효과 있었는지 알 수 없다.

## SORI 실행계획 구조

```text
오늘
이번 주
30일 측정
```

### 행동 항목 구성

```text
체크 상태
행동명
왜 지금 해야 하는지
기한
연결된 근거
성공 지표
성과 메모/수치
```

### 예시

```text
오늘
□ 경쟁 매장 5곳의 메뉴와 예약 방식을 조사
근거: 반경 내 동종 업소 42곳
성공 지표: 비교 카드 5개 완성

이번 주
□ 첫 방문 피부 진단 서비스 구성
근거: 신규 유입 확보 필요
성공 지표: 문의→방문 전환율 기록 시작

30일 측정
□ 다음 케어 예약률 확인
목표: 27% → 35%
```

### 상태

```text
TODO
IN_PROGRESS
DONE
SKIPPED
```

`SKIPPED`도 허용해야 한다. 사용자가 실패를 숨기지 않고 계획을 조정할 수 있어야 한다.

# 10. 빈 상태·오류·피드백·접근성 리서치

## 사용자 문제

- 위치가 없거나 API가 실패했을 때 빈 화면이면 무엇을 해야 할지 알 수 없다.
- 지도·바텀시트가 드래그만 가능하면 일부 사용자와 한 손 사용자가 불편하다.
- 긴 한국어 상호명·주소·금액은 작은 화면에서 쉽게 잘린다.

## 빈/오류 상태 카피

| 상태 | 제목 | 설명 | CTA |
|---|---|---|---|
| 위치 없음 | 우리지역을 설정하세요 | 매장 또는 후보지 주변 경쟁을 확인할 수 있어요 | 주소로 찾기 |
| 위치 권한 거부 | 주소로 지역을 찾아볼 수 있어요 | 위치 권한 없이도 동네를 검색할 수 있어요 | 주소로 찾기 |
| 정상 0건 | 조건에 맞는 업소를 찾지 못했어요 | 반경을 넓히거나 업종을 바꿔보세요 | 반경 바꾸기 |
| 데이터 실패 | 상권 데이터를 불러오지 못했어요 | 연결을 확인한 뒤 다시 시도하세요 | 다시 시도 |
| 목표 없음 | 목표 매출을 고객 수로 바꿔보세요 | 목표와 객단가를 입력하면 하루 필요 방문을 계산해요 | 목표 매출 계산 |
| 전략 근거 부족 | 먼저 지역 또는 목표를 설정하세요 | 데이터가 쌓이면 실행할 행동을 정리해드려요 | 우리지역 설정 |

## 피드백 원칙

```text
행동 직후에는 시스템이 무엇을 하는지 알려준다.
성공 시에는 저장/반영된 위치를 화면 상태로 보여준다.
실패 시에는 사용자를 탓하지 않고 복구 행동을 제공한다.
Snackbar는 보조 피드백이며, 핵심 상태 변화는 화면에도 남긴다.
```

## 접근성·모바일 사용감

```text
터치 대상: 최소 44~48dp
아이콘 버튼: semanticLabel + tooltip
상태 전달: 아이콘 + 텍스트 + 색상
지도 핀 드래그 대안: 현재 위치 / 주소 검색 / 이 위치로 분석
바텀시트 드래그 대안: 닫기 / 전체 목록 보기 / 지도 보기
지도 대안: 경쟁업소 목록
긴 텍스트: 2줄 말줄임 + 전체 보기
360px: 가로 overflow 없음
큰 글자: 카드/버튼/표 레이아웃 유지
```

# Cursor Agent 적용 요약

> 이 문서를 읽고 **현재 기능을 새로 설계하거나 기술 구조를 바꾸지 말 것**. 우리지역·경영 화면의 사용감, 정보 우선순위, 카피, 카드, 지도, 필터, 빈 상태, 전략 표현을 개선하는 UX 자료로만 활용한다.

```text
1. 우리지역 첫 화면은 경쟁 수 → 경쟁 밀도 → 목표 필요 방문 → 오늘 행동 순서.
2. 경영 첫 화면은 목표 대비 차이 → 고객/객단가/재방문 레버 → 실행 행동 순서.
3. 지도는 검색 → 필터 → 클러스터/마커 → 장소 카드 → 조사 목록 저장 순서.
4. 업종/반경은 즉시 적용되는 filter chip.
5. 후보지 비교는 최대 3개, 동일 조건, 단정 없는 가설형 설명.
6. 목표매출은 회계 수식보다 하루 고객·객단가·영업일 시나리오로 번역.
7. 전략은 신호 → 근거 → 해석 → 확인 → 행동 → 30일 지표 → 한계.
8. 실행계획은 오늘 / 이번 주 / 30일 측정으로 행동을 줄인다.
9. API 오류와 정상 0건을 구분하고, 빈/오류 상태마다 다음 행동 CTA 제공.
10. 모바일에서는 한 손 사용, 큰 글자, 지도 목록 대체, 드래그 대안을 제공.
```

# 조사 근거

- Square Appointments: 예약 성과 보고서에서 재방문율, 사전예약, 예약 가동률 등의 운영 지표 제공.
- Fresha for Business: 살롱용 예약, POS, 결제, 마케팅, 보고·분석 기능 제공.
- Vagaro: 고객 유지, 신규/기존 고객 비교, 재예약 성과, 대시보드 보고 제공.
- Google Business Profile: 지역 결과의 관련성, 거리, 인지도 관련 원칙.
- Apple Maps: 위치 검색과 목적지 판단을 위한 인터랙티브 장소 카드 패턴.
- Google Maps Marker Clustering: 대량 장소 마커를 줌 레벨에 따라 묶어 이해하기 쉽게 하는 패턴.
- Material Design 3: Search와 Filter Chips 컴포넌트 사용 패턴.
- Nielsen Norman Group: 점진적 공개, 빈 상태, 오류 메시지 UX.
- Apple Human Interface Guidelines: 빈 화면의 다음 행동, 피드백의 역할.
- WCAG 2.2: 드래그 대안, 포커스 가림 방지, 모바일 접근성.
- 국세청 통계로 보는 생활업종: 지역·업종 집계 매출 수준과 사업자 통계 비교의 근거.
