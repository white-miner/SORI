# SORI 디지털 차트지 — 최종 제품 기획서 v1.0

작성일: 2026-09-29

문서 성격: 지금까지의 제품 방향과 사전 조사를 통합한 구현 기준안. 이 문서 작성은 구현·DB 변경·배포 승인을 의미하지 않는다.

우선순위: 본 문서는 `SORI_DIGITAL_CHART_DEVELOPMENT_PLAN.md`의 제품 명칭·화면 구성·개발 순서를 대체한다. 기존 코드·데이터 보호 계약은 유지한다. 새로운 사용자 지시가 생기면 그 지시를 우선한다.

## 1. 제품 목표

**디지털이 낯선 원장도 스마트폰 하나로 고객의 오늘 기록을 남기고, 다음 방문 때 그 기록을 즉시 꺼내 상담할 수 있게 한다.**

SORI CHART는 피부·체형관리를 모두 담는 디지털 차트지다. 얼굴과 피부 점수를 모든 방문의 기본 전제로 두지 않는다. 피부관리와 체형관리를 같은 방문에서 함께 기록할 수 있어야 한다.

사용자에게 보여줄 주 동선:

`홈 → CHART → 고객 선택 → 지난 기록 확인 → 오늘 기록 → 기록 완료`

기록의 인과관계:

`고객에게 확인한 사실 → 상담 판단과 합의 → 실제 시행한 관리 → 관찰된 변화 → 다음 방문에서 확인할 내용`

기능의 성공은 입력칸이나 버튼의 존재가 아니라 이 연결이 실제 화면에서 이어지고 저장·재조회되는 것으로 판단한다.

## 2. 설계 원칙

1. 입력은 선택·촬영·말하기 중심으로 설계하며, 말하기가 연결되기 전에는 직접 입력만으로 모든 기록을 완료할 수 있게 한다.
2. 고객 이름과 방문 날짜를 항상 식별할 수 있게 한다.
3. 다섯 구간은 기록의 분류이며 강제 순차 설문이 아니다. 필요한 구간을 바로 열 수 있다.
4. 이전 구간의 정보는 다음 구간에서 읽을 수 있어야 한다. 다시 입력시키거나 복제본을 별도로 편집시키지 않는다.
5. 고객 발언, 관리사 관찰, 실측값, AI 초안, 승인된 판단을 구분한다.
6. 미확인·미기록·없음·변화 없음·0은 서로 다르다. 비어 있는 값을 정상 상태나 기본 수치로 채우지 않는다.
7. 목표·합의한 계획과 실제 시행한 관리를 구분한다.
8. 기본은 짧게 기록하고 상세는 필요할 때 펼친다. 긴 문진표와 카드 안의 반복 카드 구조를 피한다.
9. 녹음·촬영·저장된 것처럼 보이는 샘플 동작을 실제 기록 화면에 노출하지 않는다.
10. 과거 기록은 오늘의 고객정보 변경으로 바뀌지 않는다.

## 3. 다섯 구간의 확정 명칭

| 구간 | 다루는 질문 | 기록 주체와 내용 |
|---|---|---|
| **기본 정보** | 누구의 언제 방문인가? | 고객 식별·방문일·필요한 기본정보. 읽기 중심 |
| **문진 기록** | 고객에게 무엇을 확인했는가? | 오늘 목적·고민·희망 부위·안전정보·경험·원하는 변화 |
| **상담 기록** | 확인한 내용을 어떻게 해석하고 무엇을 합의했는가? | 관리사 관찰·판단·고객과 합의한 관리 방향 |
| **관리 내용** | 실제 무엇을 했는가? | 시행한 관리·부위·순서·제품·기기·관리 중 반응 |
| **변화 기록** | 관리 후 무엇이 달라졌고 다음에 무엇을 확인할 것인가? | 사진·관찰·고객 반응·필요한 비교·홈케어·다음 계획 |

‘상담·상태 확인’이라는 중복 명칭은 사용하지 않는다. 문진 내용을 상담에서 다시 질문하는 구조도 만들지 않는다. 문진 원문은 상담의 참고 정보이고, 상담 기록은 새로 도출한 판단과 합의다.

## 4. 홈 CHART 진입

### 4.1 고객 선택

- 기존 홈 CHART가 기본 입구다. 서랍·파일·회차는 과거 기록을 찾는 보조 탐색으로 유지한다.
- 고객 선택 또는 신규 등록 후 해당 고객의 기록 화면으로 이동한다.
- 고객 기본정보를 방문마다 다시 입력시키지 않는다.

### 4.2 고객 기록 요약

위에서부터 고객명 → 핵심 주의사항 → 최근 실제 관리와 변화 → 오늘 기록 버튼 → 과거 기록 순으로 읽히게 한다. 전화번호·주소 등의 행정정보가 상담 맥락보다 큰 공간을 차지하지 않게 한다.

최근 기록에는 날짜, 실제 관리명·부위, 특이 반응, 다음 권장 내용을 우선한다. ‘관리 목표’를 실제 시행한 관리명 대신 표시하지 않는다. 사진이 있으면 실제 사진을, 없으면 짧은 상태 문구를 표시한다.

초안이 있으면 `이어서 기록`과 `새 방문 기록`을 구분한다. 새 방문은 날짜가 같아도 독립된 방문 ID를 사용한다. 단순 페이지 재진입·버튼 연속 탭·재시도는 새 방문 생성 사유가 아니다.

## 5. 신규 고객 상담

목적: 고객을 이해하고 첫 관리 방향을 정한다. 상담 진입 즉시 문진을 읽을 수 있어야 한다.

### 5.1 표시 우선순위

| 순서 | 상담 화면에서 볼 정보 | 상담에 필요한 이유 |
|---|---|---|
| 1 | 오늘 목적·희망 부위·주요 고민·원하는 변화 원문 | 고객의 기대를 먼저 이해 |
| 2 | 기록된 주의사항·미확인 항목 | 먼저 추가 확인할 내용을 식별 |
| 3 | 기간·불편 정도·발생 상황 | 고민의 맥락 이해 |
| 4 | 이전 관리 경험·반응·선호·피하고 싶은 방식 | 첫 관리 방향 조정 |
| 5 | 오늘 관리와 관련된 생활·홈케어 정보 | 관리 및 이후 안내의 조건 확인 |
| 6 | 오늘 관찰·관리 전 사진·필요한 측정 | 고객 설명과 관찰 사실을 함께 확인 |

모든 정보를 기본 화면에 나열하지 않는다. 상단에는 목적·주의사항·짧은 문진 요약을 표시하고 나머지는 펼쳐본다. 사진이 아직 없어도 상담을 작성할 수 있다.

### 5.2 화면 구조

```text
← 고객명 · 첫 상담          저장 상태
오늘 방문일

오늘 방문 목적
희망 부위 · 주요 고민
“고객이 원하는 변화”

먼저 확인할 사항
주의정보 / 아직 확인하지 않은 항목

문진 요약                 전체 보기
기간 · 불편 정도 · 관련 경험
[관리 전 사진·관찰]

상담 기록
관리사 관찰·판단
고객과 합의한 관리 방향
[직접 기록] [말로 기록: 실제 연결 후]

[상담 내용 적용]
```

녹음 버튼은 문진을 대체하지 않는다. 음성을 쓰지 않아도 상담 작성·수정·적용이 가능해야 한다.

## 6. 재방문 고객 상담

목적: 지난 결과를 확인하고 오늘 관리를 유지하거나 조정한다. 신규 문진을 처음부터 반복하지 않는다.

### 6.1 표시 우선순위

| 순서 | 상담 화면에서 볼 정보 | 상담에 필요한 이유 |
|---|---|---|
| 1 | 현재 주의사항·오늘 변경사항·확인 여부 | 지난번과 조건이 같은지 확인 |
| 2 | 직전 방문 날짜·실제 관리·부위 | 무엇을 했는지 기억 회복 |
| 3 | 당시 목표·관리 중/직후 반응 | 기대와 당시 결과 확인 |
| 4 | 지난 방문 이후 고객 반응 | 귀가 후 변화·불편·지속 여부 확인 |
| 5 | 지난 사진·관찰값과 오늘 상태 | 비교 근거 확인 |
| 6 | 지난 홈케어·다음 계획과 오늘 확인한 실행 여부 | 오늘 방향 조정 |
| 7 | 오늘 새 고민·원하는 변화 | 현재 고객의 우선순위 확인 |

‘지난 관리 직후 반응’은 과거 방문 기록이다. ‘지난 방문 이후 반응’은 오늘 새로 확인한 기록이다. 날짜와 출처를 분리하며 하나의 만족도로 합치지 않는다.

### 6.2 화면 구조

```text
← 고객명 · 재방문           저장 상태
지난 방문 날짜 · 경과 기간

오늘 확인할 사항
변경사항 / 미확인 항목

지난 관리                 상세 보기
실제 관리명 · 부위 · 당시 목표 · 특이 반응

지난번 이후 어떠셨어요?
고객 반응 / 변화 지속 / 새 불편
[오늘 확인한 내용 기록]

[지난 사진 ↔ 오늘 사진]
[지난 홈케어·다음 계획]

오늘 상담
유지할 것 · 조정할 것 · 합의한 관리 방향
[상담 내용 적용]
```

기본 비교는 직전 관련 방문으로 한다. 지난번은 얼굴, 오늘은 하체 관리라면 관련 부위의 기록을 선택할 수 있어야 한다. 자동으로 무관한 사진을 전후 비교하지 않는다. 최초 기준 기록도 별도로 열 수 있고 비교 대상 날짜·부위를 항상 표시한다.

### 6.3 첫 상담에 준하는 재확인

고객은 재방문이어도 새로운 관리 종류·부위를 처음 받거나, 기존 기록이 없거나, 오랜 공백·변경사항이 있으면 필요한 문진을 추가한다. 임의의 경과 일수만으로 정보를 무효화하지 않는다. 같은 방문 안에서 추가 확인하며 고객이나 방문을 중복 생성하지 않는다.

신규/재방문은 신뢰할 수 있는 기존 방문 기록을 기준으로 판단한다. 고객 생성일이나 중복 가능성이 있는 회차 숫자만 사용하지 않는다. 과거 내역이 없으면 ‘이전 기록 없음’으로 표시하고 첫 이용인지 추정하지 않는다.

## 7. 구간 간 정보 승계 계약

승계는 데이터 복제가 아니라 **같은 방문 원본의 참조와 관련 과거 방문의 명시적 참조**다.

| 연결 | 다음 구간이 반드시 보여줄 근거 | 새로 작성하는 내용 |
|---|---|---|
| 기본 정보 → 문진 | 고객 식별·기존 알려진 정보 | 오늘 확인한 사실 |
| 문진 → 상담 | 고민·희망 부위·기간·원하는 변화·주의사항·확인 상태 | 관찰·판단·합의 |
| 지난 방문 → 재방문 상담 | 실제 관리·반응·사진·다음 계획 | 지난 방문 이후 고객 반응·오늘 조정 |
| 상담 → 관리 | 적용한 관리 방향·대상 부위·주의사항 | 실제 시행한 단계·제품·기기·반응 |
| 관리 → 변화 | 실제 관리·관리 중 반응·관리 전 기준 자료 | 관리 후 관찰·고객 반응·비교 |
| 변화 → 다음 방문 | 변화·홈케어·다음 계획 | 이후 반응과 새 상태 |

행동 규칙:

- 상담에서 문진을 펼쳐 읽고 수정할 수 있다. 돌아왔을 때 상담 입력과 스크롤 맥락을 유지한다.
- 문진이 바뀌면 참고 요약은 갱신하되, 이미 작성한 상담 판단은 자동 덮어쓰지 않는다.
- 상담 적용 후 그 근거인 문진이 변경되면 ‘문진 변경됨 · 상담 내용 재확인’으로 알린다. 재확인은 원장이 수행한다.
- 상담 계획이 바뀌어도 이미 기록한 실제 관리 단계는 자동 변경하지 않는다.
- 관리 전 점수·측정값이 있으면 전후 비교 기준으로 제안한다. 없으면 기본값 3 또는 0을 넣지 않는다.
- 비교 기준 변경 시 기존 결과와 충돌을 표시한다. 과거 기준값을 조용히 최신값으로 바꾸지 않는다.
- 상담을 생략한 방문도 기록 가능하다. 다음 구간은 ‘상담 기록 없음’으로 표시하고 계획을 만들어내지 않는다.
- 모든 자료에는 오늘 문진/지난 방문/고객 발언/관리사 관찰 등 출처와 필요한 시점을 표시한다.

## 8. 최소 기록과 상세 기록

기본 행동은 `오늘 관리 선택 → 필요 시 사진 → 변화 선택 또는 한 문장 → 기록 완료`다. 문진·상담은 즉시 열 수 있고 안전정보 미확인을 숨기지 않는다.

| 항목 | 기본 | 필요 시 확장 |
|---|---|---|
| 오늘 관리 | 관리명·짧은 내용 | 순서·제품·기기·강도·시간 |
| 관리 부위 | 관련 부위 선택 | 복수 부위·좌우 |
| 사진 | 관리 전/후 진입 | 부위·방향·메모 |
| 변화 | 고객 반응·관찰 한 문장 | 피부 점수·체형 실측 |
| 다음 관리 | 간단한 방향 | 홈케어·권장 시점 |

임시저장은 빈 기록도 가능하다. 정식 완료의 기본안은 고객·방문이 식별되고 실제 관리 내용, 저장된 사진, 의미 있는 상담/방문 메모 중 하나 이상이 있는 경우다. 상담만 한 방문·사진만 남긴 방문도 허용한다. 선택적 상세가 비어 있다는 이유로 완료를 막지 않는다.

안전정보 확인 상태는 계속 표시한다. 미확인 시 관리 시작/완료를 차단하는 세부 정책은 별도 운영 결정 사항이며 앱이 관리 적합성을 자동 판정하지 않는다.

## 9. 피부·체형·복합관리

- 공통 기록은 관리 부위·목표·실행·반응·변화다. 관리에 따라 필요한 상세를 제안한다.
- 피부: 수분·유분·민감·홍조 등 기존 9개 점수는 선택 항목으로 유지한다.
- 체형: 부위별 고객의 느낌·관리사 관찰·필요한 실측을 구분한다. 실측에는 단위·부위·좌우·시점·비교에 필요한 측정 조건을 붙인다.
- 체형 실측을 피부 1~5 점수 컬럼에 저장하지 않는다. 사진으로 실측값·감량·효과를 추정하지 않는다.
- 같은 방문에 얼굴·복부·등·하체 관리를 함께 기록한다. 사진·관찰은 해당 부위를 식별할 수 있어야 한다.
- 피부/체형 중 하나를 먼저 선택해야만 시작할 수 있는 관문을 만들지 않는다.
- 관리명·고민·변화 예시를 실제 고객 데이터처럼 미리 채우지 않는다.

## 10. 안전정보와 과거 기록

상태는 `미확인 / 없음 / 있음 / 해당 없음`을 구분한다. 해당 없음은 적용 가능한 항목에만 제공한다.

- Customer는 현재 알려진 정보다. Visit snapshot은 그 방문 당시 정보다.
- 알려진 값과 오늘 확인했는지는 별개다. 확인 시점·확인 상태를 구분한다.
- ‘지난 정보와 같음’은 이미 알려진 값에 대한 오늘 확인이다. 빈 항목을 없음으로 바꾸지 않는다.
- 오늘 정보 수정은 현재 고객정보와 현재 방문에만 적용한다. 과거 snapshot을 덮어쓰지 않는다.
- 과거 ‘없음’이 자동 기본값인지 실제 답변인지 근거가 없으면 오늘 확인됨으로 승격하지 않는다.
- 과거 snapshot이 없으면 ‘당시 기록 없음’으로 표시한다. 현재 고객정보로 대신 채우지 않는다.
- 동의 여부는 실제 동의 기록을 참조해 확인한다. 방문 수만큼 동의를 자동 생성하거나 유효기간을 이번 UI에서 새로 추정하지 않는다.

## 11. 지난 관리 복사

복사는 입력 보조다. 원본 방문 날짜·내용을 확인하고 원장이 선택한다.

복사 가능: 관리명·단계·제품·기기·부위·필요한 설정 참고값.

자동 복사 금지: 오늘 안전 확인·점수·실측·불편 정도·전후 사진·이상반응·상담 승인·완료 상태.

복사한 계획은 실제 시행으로 자동 확정하지 않는다. 새 방문 ID를 유지하며 원본 방문을 수정하지 않는다.

## 12. 촬영과 말하기

### 촬영

기존 촬영·압축·업로드 경로를 재사용한다. 현재 방문 ID와 사진세트를 명확히 연결하며 날짜로 다른 방문을 자동 선택하지 않는다. 얼굴 정면만 기본으로 강제하지 않는다. 부위와 방향이 맞는 사진을 비교한다.

취소/권한 거부/업로드 중/실패/재시도/저장 완료를 구분한다. 사진 실패가 다른 입력을 지우지 않는다. 촬영 권한 거부 시 앨범 선택 등 실제 가능한 대안을 제공한다. 이미지가 없는 상태에 가짜 고객 사진을 넣지 않는다.

### 말하기

`말하기 → 실제 기록 상태 → 종료 → 초안 → 수정 → 적용`으로 연결한다. 실제 음성을 저장하지 않는 타이머는 운영 화면에 두지 않는다. 문진 참고 영역은 말하기 중에도 접근 가능해야 한다.

생성 초안·편집 중 내용·승인본을 구분한다. 승인본을 편집한다고 원본 초안까지 같이 바뀌게 하지 않는다. 생성 실패 시 문진을 AI 요약인 것처럼 포장하지 않는다.

실제 음성 기능의 공급자·권한·비용·보관 및 삭제 정책은 후속 승인 범위다. 직접 기록 기능은 음성 연결과 무관하게 먼저 완결한다.

## 13. 저장·완료·복구

1. 입력 변경은 같은 draft에 저장한다. 재시도로 새 방문을 만들지 않는다.
2. 서버 저장은 요청 순서를 보장하고 최신 편집이 저장된 경우에만 저장됨으로 표시한다.
3. 저장 대기 중 이탈·백그라운드·앱 종료에도 복구할 기기 보관을 설계한다. 기기 보관과 서버 저장 상태를 구분한다.
4. 로컬 보관은 계정·샵별로 분리하고 보관 기간·로그아웃 처리·동기화 완료 후 정리를 정한다. 무조건 영구 보관하지 않는다.
5. 완료 버튼은 대기 저장·사진 상태를 정리한 뒤 서버 완료 저장이 성공하면 리포트를 연다.
6. 사진 미전송 시 기다리기/재시도 또는 사진 제외 완료를 명시적으로 선택한다. 예고 없이 사진을 버리지 않는다.
7. 저장 실패 시 화면과 입력을 유지하며 재시도한다. 오프라인에서는 ‘기기에 보관됨·전송 대기’로 표시하고 서버 완료를 주장하지 않는다.
8. 지연된 draft 요청이 completed 상태를 되돌리지 못하게 한다. 반복 완료 요청은 같은 결과를 유지한다.
9. 다른 기기에서 수정된 기록과 충돌하면 조용히 덮어쓰지 않고 재확인이 필요함을 표시한다. 구현 방식은 저장 단계에서 확정한다.
10. 완료 리포트의 ‘고객 차트’는 이동만 수행한다. 결제·회원권 차감·visit_checked·피드백 발행을 새 완료 행동에 추가하지 않는다.

## 14. 완료 리포트와 다음 방문

리포트는 고객·방문일, 오늘 목적, 실제 관리·부위, 사진, 변화·반응, 다음 계획 순으로 읽힌다. 상담 판단과 상세는 펼쳐볼 수 있다. 기록되지 않은 항목은 임의 생성하지 않는다.

작성 진행 표시를 제거하고 고객 차트로 돌아가는 주 행동 하나를 둔다. 사진 유무와 내용 길이에 따라 높이를 조절하며 첫 화면에 모든 항목을 강제로 압축해 글자를 줄이지 않는다.

다음 방문에는 같은 리포트의 실제 관리·반응·다음 계획이 상담 근거로 다시 나타난다. 새로고침 후 서버에서 다시 읽어도 내용이 같아야 한다.

## 15. 화면·접근성 기준

- 모바일 우선: 360px·390px, 태블릿 세로/가로를 확인한다.
- 상단 고객·방문일, 본문 근거와 입력, 하단 주요 행동의 계층을 유지한다.
- 긴 한국어 구간명을 같은 폭의 5개 버튼에 강제 배치하지 않는다. 현재 구간과 다른 구간 진입이 명확하면 된다.
- 모바일 상담에서는 짧은 근거 요약과 펼치기를, 태블릿에서는 근거와 기록 영역의 나란한 배치를 활용한다.
- 원문을 열었다 닫아도 작성 내용·선택 고객·방문이 유지된다.
- 터치 영역 44~48px, 글자 1.3배/1.5배, 키보드·하단 안전 영역을 검수한다.
- 색만으로 확인·위험·저장 상태를 전달하지 않는다. 최신 `SORI_VISUAL_STANDARD.md`와 홈의 글꼴·토큰을 기준으로 한다.

## 16. 현재 구현의 확인된 단절

아래는 로컬 코드 조사 결과다. 운영 배포 상태나 실기기에서 재현한 결과는 아니다.

| 지점 | 확인한 내용 |
|---|---|
| 문진→상담 | 같은 session에 값이 있으나 `_consult`에서 문진을 표시하지 않음 |
| 상담 시작 | 샘플 상태·타이머 중심이며 직접 상담 입력이 초기 화면에 없음 |
| 상담→관리 | 관리 화면에 상담 판단·합의한 방향이 표시되지 않음 |
| 관리→변화 | 실제 관리·관리 중 반응을 결과 화면에서 요약하지 않음 |
| 비교 기준 | `_addChange`가 이전 점수를 session에서 가져오지 않고 3으로 시작 |
| 완료 리포트 | 실제 관리 대신 목표를 ‘오늘의 관리’로 표시 |
| 새 방문 | `fresh`에서 샘플 관리 단계가 남는 경로 존재 |
| 사진 | 새 작성기 버튼은 각도 Set을 토글하며 실제 촬영 연결이 아님 |
| 과거 맥락 | `PastVisit` 변환이 관리 상세·상담·다음 계획·실제 사진 참조를 충분히 전달하지 않음 |
| 재조회 | 기존 `ChartVisitSheet`는 주로 기존 필드를 읽어 새 본문과 읽기 차이가 있음 |
| 저장 상태 | 완료 화면 표시와 completed 저장 행동의 시점이 다름 |

핵심 파일: `lib/features/chart_visit/chart_visit_flow_page.dart`, `chart_visit_mock.dart`, `chart_visit_live.dart`, `chart_visit_home_page.dart`, `lib/models/chart_visit_record.dart`, `lib/views/chart_workspace/chart_visit_sheet.dart`.

## 17. 데이터·호환성 구현 원칙

- `customer_charts` 한 행=한 방문을 유지한다. 기존 함수·라우트·정렬·대표 URL·사진세트 계약을 보존한다.
- 신규 화면과 기존 기록지의 읽기 차이를 어댑터로 정리한다. 의미가 다른 기존 메모 필드에 모든 내용을 넣지 않는다.
- 표시 요약은 원본에서 파생한다. 같은 문진을 화면별로 중복 저장하지 않는다.
- 기존 safety는 문자열 맵이므로 중첩 메타데이터를 임의 삽입하지 않는다. 확인 상태·시각은 호환 가능한 확장을 별도 매핑한다.
- 체형 측정, 오늘의 재방문 피드백, 상담 합의 구조 등 미지원 항목은 구현 전 저장 위치와 소비자를 확정한다. 현재 지원한다고 보고하지 않는다.
- 사진 URL과 방문 ID를 실제로 읽어 표시한다. `hasPhotos`만으로 실제 사진 표시를 대신하지 않는다.
- DB 변경이 필요하면 별도 Expand 계획을 제출한다. 기존 데이터 삭제·rename·마이그레이션 수정·일괄 덮어쓰기는 하지 않는다.

## 18. 개발 순서와 승인 단위

기존 계획의 ‘명칭부터 변경’ 순서를 대체한다. 먼저 문진을 보며 상담할 수 있는 실제 연결을 구현한다. 작업별 코드·테스트 포함 수정 파일은 5개 이하로 분할하고, 단계마다 화면으로 검수한다.

| 단계 | 범위 | 완료 증거 |
|---|---|---|
| 1 | 오늘 문진을 신규 상담에 표시, 녹음 없이 직접 상담 작성 | 실제 입력한 문진을 상담에서 확인·수정·복귀 가능 |
| 2 | 재방문 상담에 직전 관리·반응·다음 계획 연결 | 관련 과거 기록을 보며 오늘 반응 작성 가능 |
| 3 | 상담 합의→관리, 실제 관리→변화 연결 | 재입력 없이 근거가 보이고 실제 시행은 별도 기록 |
| 4 | 미확인 구분·샘플 기본값 제거·피부/체형 공통 표현 | 빈 정보가 사실로 바뀌지 않음, 체형에 피부 입력 강제 없음 |
| 5 | 저장 순서·완료 시점·재조회 일치, 임시보관 복구 | 실패·종료·재실행·연속 탭에서 유실/중복 없음 |
| 6 | 기존 촬영 연결·부위별 사진·리포트 표시 | 실제 촬영→정확한 방문 저장→다음 상담 재조회 |
| 7 | 최소 기록 동선·선택 복사·선택적 상세 | 간단 기록과 상세 기록이 같은 방문을 편집 |
| 후속 | 실제 음성·체형 실측 상세 등 별도 확장 | 정책과 저장 매핑 승인 후 기능별 검수 |

이 순서는 논리적 작업 묶음이다. 안전한 연결에 필요한 작은 모델/어댑터 수정은 해당 단계에 포함하되 승인 범위와 5파일 제한을 지킨다. 위험한 샘플 동작이 남은 중간 단계는 운영 완성으로 배포하지 않는다.

수정하지 않는 범위: 결제·회원권·전자동의의 기존 처리, 우리지역·커뮤니티, 전역 라우팅 교체, 기존 B&A 저장 규칙. 전체 저장소 리팩터링은 하지 않는다.

## 19. 검수와 배포 조건

필수 실사용 시나리오:

1. 신규 피부관리: 문진 작성→상담에서 원문 확인→수기 판단 적용→관리→변화→완료→재조회.
2. 신규 체형관리: 피부 고민 선택 없이 부위·목적→상담→실제 관리→부위별 기록.
3. 재방문: 지난 관리·직후 반응 확인→이후 고객 반응 기록→오늘 방향 조정.
4. 복합관리: 한 방문 안의 얼굴·체형 관리를 구분하고 사진을 올바른 부위끼리 비교.
5. 새로운 관리 영역: 재방문 고객에게 필요한 추가 문진만 노출.
6. 문진 수정: 상담 입력 유지, 이미 적용한 판단의 재확인 표시, 자동 덮어쓰기 없음.
7. 사전 점수 없음: 전후 수치를 임의 생성하지 않음.
8. 사진 취소·권한 거부·업로드 실패: 다른 기록 보존과 정상 복귀.
9. 네트워크 중단·앱 종료·마지막 입력 직후 이탈: 기록 복구와 정확한 저장 상태.
10. 완료 연속 탭·지연된 저장 응답: 중복 방문과 completed→draft 역전 없음.
11. 다른 고객·계정으로 전환: 이전 고객의 문진·초안·사진이 섞이지 않음.
12. 기존 차트·B&A·동의·회원권 플로우 회귀 없음.

기존 테스트의 저장·복원 확인만으로 통과 처리하지 않는다. 문진에 입력한 실제 문장이 상담 UI에 보이는지, 상담 합의가 관리 UI에 보이는지 등 구간 연결 테스트를 추가한다.

기본 검증 명령은 `flutter analyze`, 관련 chart/workspace/photo 테스트, `flutter test`, 실제 workflow 조건의 웹 release build다. 현재 문서 작성 중 실행한 결과가 아니라 구현 단계의 요구사항이다.

캡처: 신규 상담, 재방문 상담, 문진 펼침, 관리 근거, 변화 비교, 완료 리포트. 360px·390px·태블릿에서 확인한다. 화면을 보지 못했거나 서버 재조회를 못 했으면 미확인으로 보고한다.

실사용 검수 제안: 디지털에 익숙하지 않은 원장 3~5명에게 설명 없이 기록·재조회 과제를 준다. 성공률·도움 요청·누락·소요시간을 측정한다. 간단 기록 1분 이내(촬영 제외), 고객 선택 후 지난 기록 확인 10초 이내를 초기 목표로 둔다. 현재 성능 주장이 아니며 관찰 후 조정한다.

배포 조건: 핵심 동선 실제 조작, 저장 후 새로 읽기, 모바일 렌더링, 회귀 테스트 확인. 유실·고객 오연결·가짜 완료·허위 기본값이 남으면 배포하지 않는다. 롤백은 단계별 변경 되돌림 또는 신규 진입 비활성화로 수행하고 작성된 방문·사진은 보존한다.

## 20. 조사 근거와 남은 구현 결정

제품 설계는 로컬 코드 조사와 아래 에스테틱 교육기관의 상담·기록 자료를 참고했다. 자료는 피부·바디 상담의 관련 정보 범주를 참고한 것이며, 한국 법령이나 관리 적합성 판정 규칙으로 사용하지 않는다.

- [VTCT Skills — 피부관리 상담·기록 기준](https://www.vtctskills.org.uk/cg__proxy_download.php?file=..%2Fqualfinder%2F1Record+of+Assessment+Book%2FAB20178R.pdf)
- [VTCT — 얼굴·바디관리 상담 평가 기준](https://www.vtct.org.uk/wp-content/uploads/2022/03/End-point-Assessment-sequence_ABT_v1.pdf)

구현 전 단계별로 확정할 기술 사항: 재방문 피드백 저장 위치, 안전 확인 메타데이터 호환 방식, 상담 승인본 보존 방식, 체형 실측 구조, 다중 기기 충돌 처리, 기기 임시보관 정책, 음성 공급자·보관 정책. 이 결정을 위해 기본 문진→상담 UI 연결 작업 전체를 보류할 필요는 없다.

**최종 제품 기준: 원장이 무엇을 보며 상담하고, 그 판단이 어떤 관리로 이어졌으며, 다음 방문에 무엇을 다시 확인할지 한 고객의 기록 안에서 끊기지 않아야 한다.**
