# SORI — ChatGPT 직관적 작업방식 LOCK

**Status:** LOCKED · 바꾸지 말 것  
**잠근 날:** 2026-09-18  
**증거:** 우리지역 복구 tip `6aeb6ab` (`b5df3a9`…`9fe4e00`)  
**PO 지시:** “챗지피티의 직관적인 작업방식을 기준으로 기록하고 바꾸지마”

이 문서는 **해설·개선안·하이브리드 프로세스가 아니다.**  
ChatGPT가 우리지역을 닫을 때 쓴 작업방식을 **있는 그대로** 기준(SSOT)으로 고정한 것이다.  
에이전트·기획·퍼플렉시티·후속 문서가 이 방식을 변형·완화·확장하지 않는다.

---

## 0. 절대 조항

```text
1. 이 LOCK이 작업방식의 기준이다.
2. 다른 규칙(5파일·승인 대기·100체크·STOP 조사 게이트)과 충돌하면,
   “사용자 출구가 깨진 복구/완성 작업”에서는 이 LOCK이 우선한다.
3. 이 문서의 방법 섹션을 고쳐 “더 안전한 프로세스”로 바꾸지 않는다.
4. 부록·사후분석·PRD는 참고만 한다. LOCK을 덮어쓰지 않는다.
```

CONTRACTS(스키마 삭제 금지·시그니처 파괴 금지·시크릿 금지)는 유지한다.  
그건 작업방식이 아니라 **데이터 안전장치**다.

---

## 1. ChatGPT가 한 일 (기록 — 해석 금지)

우리지역에서 실제로 한 순서:

1. **사용자 출구 한 줄만 본다**  
   “맵/목록에 중심 기준으로 뷰티 샵이 보이거나, 안 되면 정직하게 실패를 보여라.”
2. **끊긴 통로를 따라간다**  
   Edge `get-shop-market` 페이지네이션 · 실패 상태 · 클라 서비스.
3. **입구를 하나로 고정한다**  
   search center SSOT · map-first.
4. **출구에서 가짜·샘플·구식 UI를 걷어낸다**  
   sample-only 제거 · 캡션 정정 · obsolete 테스트 폐기.
5. **업종을 정확히 가른다**  
   beauty 분류 · upstream lookup 축소.
6. **돌아가게 만든 뒤 끝낸다**  
   문서 100칸·추가 조사 대기·마이크로 기능 PR로 새지 않음.

완성의 정의는 체크리스트 %가 아니라 **출구가 닫힌 상태**다.

---

## 2. 직관적 작업방식 (LOCK 본문 — 수정 금지)

### 2.1 먼저 출구

```text
화면에 무엇이 보여야 / 들려야 끝나는가.
그 한 줄이 없으면 코딩하지 않는다.
```

### 2.2 입구 → 통로 → 출구를 한 호흡에

```text
위젯만 고치지 않는다.
데이터가 어디서 들어와(입구),
어디서 계산·전송되고(통로),
어디에 그려지는지(출구)를 같은 작업에서 닫는다.
```

### 2.3 장식보다 파이프

```text
칩·카피·반경 UI를 늘리기 전에
페이지네이션·필터·중심점·실패 상태가 맞는지를 본다.
파이프가 비면 UI는 거짓 진척이다.
```

### 2.4 정직

```text
모르면 가짜 LIVE를 만들지 않는다.
partial / fail / empty를 사용자 언어로 보여준다.
```

### 2.5 지우기

```text
출구를 가리는 샘플·구식 레이아웃·죽은 테스트는 제거한다.
“나중에 쓸지 몰라”로 깨진 출구 위에 쌓지 않는다.
```

### 2.6 범위 한 줄

```text
지금 출구와 무관한 도메인(다른 탭·경영 전략·차트·타이머)을 같은 호흡에 넣지 않는다.
```

### 2.7 조사는 보조

```text
동작 재현은 코드·로그·테스트로 한다.
외부 조사는 카피·금지·선택지에만 쓴다.
조사 회신이 올 때까지 출구를 열어 두지 않는다.
```

### 2.8 끝나면 끝

```text
출구가 닫히면 그 이슈는 끝이다.
같은 이름으로 다음 기능을 몰래 붙이지 않는다.
```

---

## 3. 한 장 카드 (세션 시작 시 그대로 붙일 것)

```text
SORI 작업방식 = ChatGPT LOCK (바꾸지 말 것)
1) 출구 한 줄
2) 입구→통로→출구 한 호흡
3) 파이프 먼저, 장식 나중
4) 정직한 실패
5) 샘플/구식/죽은 테스트 제거
6) 범위 한 줄
7) 조사는 카피만, 구현은 재현
8) 출구 닫히면 종료
```

---

## 4. 금지 (이 LOCK을 깨는 행동)

- 이 문서를 “더 엄격한 프로세스”로 재작성
- 100개 체크리스트·STOP-조사게이트로 출구 대기를 강제
- 출구 미완인데 UI 마이크로 PR만 머지
- “계약 준수 중”을 사용자 출구 미완의 변명으로 사용
- Expand 규칙만 들이대며 깨진 E2E 파이프를 쪼개 방치
- 퍼플렉시티/장문 PRD로 이 LOCK을 덮어쓰기
